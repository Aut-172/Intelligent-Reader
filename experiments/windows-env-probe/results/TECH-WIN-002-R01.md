## 2 原始事实（F）

1. 路径与内容相互独立：移动或改名不改变内容哈希，但旧路径立即失效；同路径下的内容替换会改变哈希。
2. 只改修改时间（不改字节）时哈希不变；即「修改时间」不能作为版本判据，而「精确哈希」可以。
3. 换行符差异会改变哈希：逻辑文本相同、字节不同的文件被判为不同内容。
4. 相同字节在不同文件名、不同目录下哈希一致；删除后重建相同内容哈希仍一致。
5. 重复读取哈希稳定。

## 3 项目组解释（I）

1. **D-16 A 的「精确内容哈希」在 Windows 上可直接落地**：复制、改名、移动均可被识别为同一内容；不需要依赖路径稳定性。
2. **同路径不等于同一版本**：外部程序覆盖保存、同步客户端回写、重新导出都会在路径不变时改变哈希，必须建立新 `DocumentVersion`，不能沿用旧版本与旧引用（D-16 A、D-25 A）。
3. **修改时间不可用于身份**：用户复制/恢复/同步都会改修改时间；仅以「大小 + 时间」判重会同时产生漏判与误判。
4. **精确哈希是严格的**：同义文本、换行转换、重新导出会被判为新内容。这是 D-16 A 的预期后果，但界面必须解释「内容已变化，需重新生成引用」，避免用户误以为应用丢笔记。
5. **哈希相同不代表同一物理文件**：删除后重建相同字节会得到相同身份；这在 D-16 A 下是预期行为（同一内容即同一版本语义），但不能据此推断文件血缘或访问权限。

## 4 技术/需求结论（C）

1. Windows 端 `DocumentIdentity` 应以精确内容哈希为主键，路径与修改时间仅作展示与辅助提示（对应 FR-01、AC-02、D-16 A）。
2. 每次打开文档都应重算哈希或校验缓存哈希；发现变化即建立新版本并将旧引用标 stale（对应 BR05、AC-18、D-25 A）。
3. 需要在 UI 上区分「同一内容换了位置」与「同一位置换了内容」两类事件，前者可提示重绑，后者必须新建版本。
4. 该结果不能替代 W-E06 的引用回跳金标（插页、删页、重排、OCR 变化仍需桌面壳与文档组件实验）。
