# TECH-WIN-003-R01 Windows 平台安全凭据边界探针结果

- 编号：`TECH-WIN-003-R01`
- 日期：2026-11-17 21:34（UTC+08:00）
- 负责人：B（Windows 端架构调研与比较负责人）
- 脚本：`experiments/windows-env-probe/probe_windows_dpapi.ps1`
- 原始 JSON：落在 `%TEMP%\reader-win-probe\TECH-WIN-003-R01.json`（原因同 TECH-WIN-001）。
- 覆盖决策：D-31 A（平台安全凭据、秘密不得进入普通文件与日志）、D-20 A（分层本地存储、凭据进平台安全存储）
- 对应 A 的待测清单：W-E10 的 Windows 侧前置能力事实
- 边界：只验证 DPAPI 用户/机器作用域的加解密、明文泄漏、篡改、熵绑定与复制行为；**不写 Windows Credential Manager、不测其他用户账户、不测重装或备份恢复**；单机单次。

## 1 观测结果

| 检查 | 观测值（原始事实） |
|---|---|
| DP-01 用户作用域加密 | 39 字节明文 → 262 字节密文（Base64 前缀 `AQAAANCMnd8BFdERjHoAwE/C`，即 DPAPI blob 头） |
| DP-02 密文文件明文扫描 | 262 字节文件中 **不含** 令牌的 ASCII 与 UTF-16 形式 |
| DP-03 解密 | 还原明文与原始令牌完全一致 |
| DP-04 复制密文文件 | 同一用户下副本仍可解密 |
| DP-05 篡改密文 1 字节 | 解密失败（异常） |
| DP-06 更换熵值 | 解密失败（异常） |
| DP-07 同一明文两次加密 | 密文不同（长度均 262 字节） |
| DP-08 机器作用域 | 本用户可用，加解密成功 |
| DP-09 删除密文文件 | 文件不存在 |
| DP-10 DPAPI 主密钥目录 | `%APPDATA%\Microsoft\Protect` 存在（per-user） |

## 2 原始事实（F）

1. DPAPI 用户作用域可对本机当前用户直接加密/解密，不需要管理员权限。
2. 密文文件不包含明文的 ASCII 或 UTF-16 形式。
3. 密文被篡改或熵值不匹配时解密失败，说明完整性由 DPAPI 提供，应用无需另加校验即可发现损坏。
4. 同一明文两次加密产生不同密文（随机化），因此不能用密文相等判断令牌是否相同。
5. 复制密文文件不改变可解密性：**文件权限与拷贝不是保护边界，用户会话才是**。
6. 机器作用域在本机同样可用。

## 3 项目组解释（I）

1. 令牌、刷新令牌等秘密可放 DPAPI 保护的独立文件或 Credential Manager；两者都绑定 Windows 用户上下文（D-31 A、D-20 A）。
2. 「密文可被复制后解密」意味着：只要攻击者取得当前用户会话（或该用户的 DPAPI 主密钥），复制文件即可读出秘密。因此应用仍需做目录权限、日志脱敏与诊断包排除（W-E10 的扫描项）。
3. 机器作用域会削弱「换用户不可解」的保护，除非有明确共享设备需求，否则应优先用户作用域。
4. 应用层不应自行实现令牌加密；也不应把密文当作「可安全外发」的数据。
5. 退出登录与设备撤销路径必须删除本地密文条目，并确认删除后无残留（对应 AC-08、D-18 A）。

## 4 技术/需求结论（C）

1. Windows 端「安全凭据」可采用 DPAPI 用户作用域或 Credential Manager，二者均为平台实现，共享核心只定义读写契约（与 D-31 A 一致）。
2. 秘密不得写入配置、日志、崩溃转储与诊断包；本轮已证明「密文文件不含明文」是可自动检查的判据，可纳入 W-E10 的扫描脚本。
3. 本轮未验证其他用户账户与重装后的不可解性；这两项是 W-E10 的正式关闭条件，仍需在受控账号环境执行。
