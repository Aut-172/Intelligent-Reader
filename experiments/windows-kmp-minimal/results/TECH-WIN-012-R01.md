# W-E08 测试报告：SSE 流式、取消、超时与轮询回退

- 实验编号：W-E08（结果编号 `TECH-WIN-012-R01`）
- 关联决策：D-27 A（REST/JSON 主协议；AI 使用 SSE，提供轮询回退）
- 关联 ADR：ADR-027
- 执行人：B
- 日期：2026-11-18
- 状态：**部分完成**——本地模拟验证 SSE 解析、取消、超时与轮询回退；真实代理/TLS/VPN 与真实供应方未验证

## 1 目的

验证客户端在 Windows 上的 SSE 行为：数据行解析、用户取消、读超时、HTTP 错误时的轮询回退，以及双失败时的失败状态。

## 2 环境

| 项 | 值 |
|---|---|
| 主机/系统 | HYC-1 / Build 26300.9974 |
| JDK/Gradle/Kotlin | 21.0.12.1 / 8.14.7 / 2.1.20 |
| 实现 | `java.net.HttpURLConnection`（JDK 内置，无新依赖） |
| 模拟服务 | 测试内 `ServerSocket` 起本地 HTTP 桩（并发处理、可延迟） |
| 真实网络/代理 | **未使用**（按授权跳过 Fiddler 真实代理） |

## 3 结果

| 用例 | 断言 | 结果 |
|---|---|---|
| SSE 数据行顺序 | `data: alpha/beta` → `[alpha, beta]`，`[DONE]` 忽略 | ✅ |
| HTTP 500 回退轮询 | 模式 `POLLING`，最终文本来自 `/poll` | ✅ |
| 读超时回退轮询 | SSE 延迟 800 ms、readTimeout 200 ms → `POLLING` | ✅ |
| 用户取消 | `onToken` 首次返回 false → 只收到 1 个 token | ✅ |
| 畸形行忽略 | `event:`、`:comment` 不影响数据行 | ✅ |
| 双失败 | SSE 与轮询均 503 → `FAILED` | ✅ |

- `windowsApp` 测试：**13/13 通过**（SSE 6 + SQLite 任务 7）；
- 构建：`BUILD SUCCESSFUL`；
- 调试记录：首轮超时用例失败，原因是测试桩单线程导致轮询请求被慢 SSE 阻塞；改为每连接独立线程后通过，产品代码未改。

## 4 判定（对照 W-E08 通过证据）

| 通过证据 | 是否取得 | 说明 |
|---|---|---|
| SSE 解析与顺序 | ✅ | 本地桩 |
| 取消 | ✅ | 客户端停止读取 |
| 超时 | ✅ | 读超时触发回退 |
| 轮询回退 | ✅ | HTTP 错误与超时两条路径 |
| 网络日志/UI 状态 | ❌ | 无 UI |
| 真实系统代理、TLS 拦截、VPN、休眠 | ❌ | 需 Fiddler/真实网络（按授权跳过） |
| 真实供应方 SSE | ❌ | 本轮不含 API |

## 5 边界

1. 模拟桩只覆盖 HTTP 语义，不覆盖 TLS、代理缓冲、连接复用与真实供应商行为；
2. 未实现重连/退避策略，仅验证「失败→轮询/失败」；
3. 取消是客户端停止读取，未验证服务端是否收到断开并停止计费；
4. 无 UI 流式展示与「半条回答」状态。

## 6 结论

- **原始事实（F）**：6 个用例全部通过；SSE 顺序正确；HTTP 错误与读超时均回退轮询；取消后只收到已读 token；双失败返回 FAILED。
- **项目组解释（I）**：D-27 A 的「SSE + 轮询回退」在 Windows JDK 客户端可实现，且不依赖外部工具；代理/TLS 风险需真实网络验证。
- **技术/需求结论（C）**：W-E08 的协议层成立；ADR-027 仍 Proposed，缺真实网络与 UI 状态。
