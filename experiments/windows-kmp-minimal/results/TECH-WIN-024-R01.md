# W-E03 静态高亮、缓存与失败降级

- 实验编号：W-E03 补充（结果编号 `TECH-WIN-024-R01`，承接 `TECH-WIN-017-R01`）
- 执行人：B
- 日期：2026-11-18
- 状态：**部分通过**——静态高亮、缓存、失败降级完成；取消受 API 限制；交互式高亮仍属 UI

## 1 目的

把词级 bbox 变成可核验的高亮证据，并验证 OCR 结果的缓存与失败降级；确认取消能力的 API 边界。

## 2 方法

1. `ocr_annotate.ps1`：读取 `we03-render-ocr.json` 的 11 个词框，在 `we03-render.png` 上画半透明高亮 + 红框，输出 `we03-boxes.png`；
2. `ocr_cache_degrade.ps1`：以图片 SHA-256 为键缓存 OCR 文本，测首次/二次耗时；对不存在的图片调用 OCR，验证不崩溃；
3. 检查 WinRT OCR 是否提供取消令牌。

## 3 结果

| 项 | 结果 |
|---|---|
| 静态高亮 | 11 个词框全部绘制，位置与文本对齐（见 `we03-boxes.png`） |
| 首次 OCR（含写缓存） | **125.5 ms** |
| 二次（缓存命中） | **34.7 ms**（约 3.6× 加速；含 JSON 解析） |
| 文本一致 | ✅ `text_match=true` |
| 失败降级 | ✅ 缺失图片被捕获，调用方不崩溃 |
| 取消 | ❌ `RecognizeAsync` 无 `CancellationToken`；只能放弃任务，不能真正取消 |

原始数据：`experiments/windows-ocr-probe/results/we03-cache-degrade.json`；高亮图：`we03-boxes.png`；缓存目录：`we03-cache/`。

## 4 判定

| 维度 | 结果 |
|---|---|
| 静态高亮/坐标映射 | ✅（11 词） |
| 缓存 | ✅（SHA-256 键；3.6×） |
| 失败降级 | ✅（异常被捕获） |
| 取消 | ❌ API 不支持；需应用层超时/丢弃 |
| 交互式选中/回跳 | ❌ UI 壳，A/C/D |

## 5 结论

- **原始事实（F）**：11 个词框可准确叠加到渲染页；OCR 结果按图片哈希缓存后二次耗时从 125.5 ms 降至 34.7 ms；缺失图片不会导致崩溃；WinRT OCR 无取消令牌。
- **项目组解释（I）**：静态高亮与坐标契约足以支撑 UI 层的选区绘制；缓存应按内容哈希而非路径；取消只能由调用方以超时/丢弃实现，不能依赖 OCR 引擎。
- **技术/需求结论（C）**：W-E03 的静态高亮、缓存、失败降级成立；交互式高亮与真正取消仍是缺口，D-22/D-14 保持 Proposed。
