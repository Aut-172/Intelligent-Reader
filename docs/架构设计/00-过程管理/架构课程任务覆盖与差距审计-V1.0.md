## 1. 审计结论摘要

当前成果已经具备较完整的架构决策输入、D-11 至 D-35 的 Proposed ADR、架构驱动因素、质量属性增量、拟议责任与部署草图，以及较完整的 Android 端平台调研和局部真机证据。但课程要求的完整成果包尚未形成，主要缺口集中在 Windows 端对称调研、完整架构图件包、业务能力/代码模块/部署单元映射、软件架构调研分析报告、系统架构设计说明书、ADR 总索引、双端验证总索引、评审 PPT 与评审记录材料。

`架构调研与设计阶段四人分工方案-V1.0.md` 的 A/B/C/D 结构仍适合作为后续执行骨架：

- A 负责决策、追踪、报告、PPT 和成果集成。
- B 负责 Windows 端架构调研与验证缺口。
- C 负责 Android 端架构调研与验证缺口。
- D 负责架构视图、图件字典和一致性维护。

但该分工稿的决策状态已经过时：其日期为 2026-11-11，仍把 D-11 至 D-15 视为待决策；当前正式基线已经明确 D-11 至 D-35 均已完成方向选择，但对应 ADR 仍为 Proposed。后续应保留 V1.0 历史文件，并在负责人批准后新增 V1.1，不应覆盖原文件。

总体覆盖判断：

| 类别 | 判断 |
|---|---|
| 决策输入和 ADR | 覆盖较高，但状态追踪、代表性 ADR 展示和测试/视图映射尚未收口 |
| Android 平台调研 | 当前最完整，但页首决策状态、验证索引状态和正式待测清单之间存在不一致 |
| Windows 平台调研 | 明显缺失，尚未形成与 C 工作包对称的正式调研文档 |

| 架构报告 | 尚未形成课程要求的两份主体报告 |
| 部署与云映射 | 已有方向和局部映射，仍缺产品逐项评估、成本、运维和信任边界完整表达 |

| 课堂评审与交付 | PPT、大纲、检查表、评审记录模板和支撑材料总索引均缺失 |

## 2. 基线优先级与使用规则

### 2.1 优先级

1. 正式基线目录中的最新版本文件是决策、边界和状态的权威来源。
2. 仓库 `docs/架构设计/阶段成果-V0.4-双端需求补充` 是协作副本，用于团队读取和协作，不得无声替代正式基线。
3. 仓库中的平台调研、验证索引和实验结果是架构证据输入；其结论必须受正式决策和证据等级约束。
4. `2组架构调研与设计` 下的旧稿只作为历史参考，不得继续作为当前架构图或范围基线。
5. `_incoming`、`.tmp`、实验中间产物和未批准草稿不得升级为正式成果。

### 2.2 状态解释

- D-00 至 D-10：沿用已批准的正式基线，不在本轮重新讨论。
- D-11 至 D-35：已完成方向选择，对应 ADR 仍为 Proposed。
- D-19：tombstone 具体保留天数仍未定。
- D-28、D-29、D-33、D-35：仍受实验、费用、性能或一致性收口门槛约束。
- 10 秒可读、30 秒首反馈、60 秒完成和 20 份文档：仅为候选实验测量点，不是正式 SLA。
- 当前部署方向：只能称为拟议或条件部署方向，不能称为最终部署图。

### 6.3 已发现的边界冲突

旧架构材料中出现 Flutter、Windows/macOS/Android/iOS 四平台、好友发现、免登录分享、共享工作区、所有者/管理员/成员、产品级分享链接等内容。这些均与当前正式边界冲突。

当前处理规则：

| 旧材料表达 | 当前正式解释 | 处理方式 |
|---|---|---|
| Flutter 或其他既定跨端框架 | 共享核心是复用目标，最终框架仍受正式决策和实验约束 | 仅作为历史候选，不进入当前正式图 |
| macOS、iOS、Web 客户端 | 一期仅 Android 12+ 和 Windows 11 | 标注后续演进或删除出一期视图 |
| 团队空间、成员和独立管理员 | 一期是个人账号和单用户本地工作区 | 不进入业务能力和权限模型 |
| 产品级分享入口、免登录分享链接 | 一期重点是 Markdown/PDF 主动导出 | 将“分享与导出”解释为导出能力 |
| 云端文档本体或全文索引 | 云端不得默认保存文档本体、全文索引或可还原全文数据 | OBS/CSS 仅做受限可选映射，不作为默认方案 |
| 每项课程能力对应一个微服务 | 服务端方向是少量粗粒度服务 | 明确业务能力、代码模块和部署单元的区别 |
