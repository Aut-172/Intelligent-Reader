## 2 D-22 至 D-35 落地定义

### D-22 A 文档能力边界

Android 与 Windows 分别选用平台原生或平台成熟组件承担 PDF 解析、渲染、文本定位和页面图像能力。共享核心只拥有统一文档合同，包括页面标识、坐标系、文本范围、能力标记、解析器版本、OCR 来源和降级原因。OCR 与版面归一化通过平台适配器接入；组件不能提供稳定文本坐标时必须显式降级为页面或文本级引用。

### D-23 B 本地混合检索

全文/BM25 候选召回与固定中文嵌入模型的语义召回均在客户端执行，再以确定的融合和重排规则生成候选证据。索引、向量和模型资产不上传云端。具体索引库、嵌入运行时、模型资产和权重参数属于实验实现，不因方向选择自动冻结。

### D-24 A 客户端证据选择

客户端在任何外发前完成文件权限校验、用户同意校验、版本校验、混合检索、重排、去重和证据裁剪。AI/RAG 网关校验证据包合同、执行长度限制和供应方调用，不主动访问客户端文档，也不扩展用户同意范围。

### D-25 A 引用与 stale

引用保存结构锚点和字符锚点，并绑定 DocumentIdentity、DocumentVersion、解析器版本和证据摘要。内容变化建立新版本后，旧引用默认标记 stale，不自动迁移。只有后续显式批准的迁移流程才能产生新锚点，并必须保留来源和置信度。

### D-26 A 异步任务

Android 与 Windows 使用各自可靠的持久任务机制；服务端使用 PostgreSQL 任务表与 worker，通过状态、lease、重试、幂等键和取消语义恢复任务。事件只用于状态通知和审计，不建立通用事件总线。D-21 不自动要求 Kafka、RabbitMQ 或其他消息代理。

### D-27 A 通信与演进

身份、同步、任务查询和普通 AI 请求使用版本化 REST/JSON；AI 增量响应使用 SSE，并提供轮询状态或最终结果回退。同步继续使用 push/pull 与不透明 cursor。合同必须定义错误码、幂等键、取消、超时、Retry-After、未知字段和版本不兼容行为。

### D-28 A 共享核心

Kotlin Multiplatform 候选共享领域模型、DocumentIdentity/Version 规则、同步状态机、公共合同、序列化和测试向量。UI、文件访问、本地数据库、文档组件、凭据安全存储、后台任务和安装打包保持平台实现。必须在 Android 与 Windows 正式目标上完成构建、测试复用和平台桥接量验证后才能关闭。

### D-29 A 模型候选

一期候选为 OpenAI 官方 Responses API，通过 ModelAdapter 隔离，并以 `gpt-5.4-mini-2026-03-17` 作为待验证固定快照。此项不由 D-15 A 自动推导；在正式项目账号完成 API 可用性、区域与数据政策、结构化输出、流式、取消、限流、质量和费用验证前，不得转 Accepted，也不得把 Codex 客户端能力当作应用 API 证据。

### D-30 A 数据库、任务与缓存

PostgreSQL 承载账号与同步数据、幂等结果、资源当前态、账号级变更记录和数据库任务表。资源状态、幂等结果和变更记录必须在同一事务提交。课程一期不设置通用业务缓存，不引入独立消息代理；只有测量证明数据库成为已验证瓶颈时才重新评估。

### D-31 A 安全基线

使用 TLS、数据库与备份的基础设施静态加密、KMS/Secret Manager 类能力、最小权限、密钥轮换、Android Keystore、Windows Credential Manager/DPAPI 与日志脱敏。当前不增加笔记或同步字段的应用层字段加密，但必须通过威胁建模、备份检查、秘密扫描和日志内容扫描证明边界。

### D-32 A 可观测性

服务端和客户端记录内容无关的结构化状态、错误类别、耗时、重试计数和脱敏关联 ID。不得记录文档正文、笔记正文、证据正文、访问令牌、完整本地路径或供应方秘密。客户端诊断包只在用户主动操作后生成，默认可预览、可裁剪且不自动上传。

### D-33 B 分级预算

文本型 PDF、复杂版式 PDF 和扫描 PDF 使用不同的可读时间、首反馈、完成时间、内存、磁盘和电量预算。10 秒、30 秒、60 秒与 20 份文档只是实验候选测量点，不是 SLA。正式阈值须依据双端 p50/p95、失败样本和降级行为确定。

### D-34 A 验证门槛

采用风险驱动的双端最小正式矩阵：共享核心、文档金标、混合检索、证据外发、引用 stale、任务恢复、REST/SSE、真实同步事务、安全、诊断、性能和干净环境重建。每个 Proposed ADR 必须可追踪到至少一项通过证据；Android 证据不能替代 Windows，反之亦然。

### D-35 A 条件部署方向

身份与同步、AI/RAG、任务与审计仍是三个逻辑责任单元，但允许在课程一期同一计算节点或同一主机上部署；共同使用 PostgreSQL 与数据库任务表。只有关键实验通过、D-33 阈值确定、D-34 门槛满足并完成需求—ADR—代码—部署—测试一致性评审后，才能发布最终架构与最终部署图。

## 3 组合约束

1. D-22 A 与 D-28 A 要求共享的是合同和测试向量，不是文档引擎或 UI。
2. D-23 B 与 D-24 A 要求全文索引、向量索引和证据选择留在客户端；D-17 A 不得被扩展为云端全文索引。
3. D-24 A 与 D-29 A 要求供应方只接收本次授权的最少证据；模型不能自行拉取本地文档。
4. D-25 A 与 D-16 A 共同禁止内容变化后静默沿用旧引用。
5. D-26 A、D-30 A 与 D-21 A 可以使用 PostgreSQL 完成事务、变更流和任务恢复，不要求事件总线。
6. D-31 A 不改变 D-20 A 的本地分层存储方向，也不表示取消平台安全存储和生命周期清理。
7. D-33 B 的阈值必须由 D-34 A 的双端矩阵产生，不能由候选数字直接转成验收 SLA。
8. D-35 A 依赖 D-28、D-29、D-33、D-34 的关闭或正式风险接受。
