## 2 D-11 B 少量粗粒度服务

### 2.1 决策内容

服务端采用少量粗粒度责任单元，拟议分为：

1. 身份与同步服务：账号、设备会话、最小文档元数据、进度、笔记、冲突副本、同步游标和 tombstone。
2. AI/RAG 网关服务：接收已经通过客户端权限过滤和逐文件同意的最少证据，调用外部模型适配器并完成流式响应、取消和错误归一化。
3. 任务与审计责任单元：执行服务端异步任务、重试、删除传播、脱敏审计和诊断。可以独立工作进程部署，但不自动等同于独立微服务。

### 2.2 收益

- 比模块化单体提供更清晰的故障与伸缩边界。
- AI 调用故障、限流或高延迟不应阻断账号和同步主链路。
- 任务进程可以独立重启和控制并发。
- 保持服务数量有限，避免进入细粒度微服务和事件总线治理成本。

### 2.3 技术要求

- 服务间只通过稳定契约通信，不共享业务代码中的隐式数据库事务。
- 身份与同步数据的所有权必须在 D-17、D-18、D-19、D-21 中明确。
- 跨服务流程使用幂等操作、关联 ID 和可恢复状态，不依赖分布式事务。
- 消息队列、关系数据库、缓存和服务间协议由 D-26、D-27、D-30 决定。

### 2.4 风险及验证

- 风险：服务拆分早于数据边界，形成分布式单体。
- 风险：任务与审计职责过宽，逐渐成为公共杂物服务。
- 验证：分别停止 AI/RAG、任务进程和同步服务，确认故障隔离、重试和用户可见降级。
- 验证：检查服务是否通过数据库表直接耦合，跨服务更新是否可重放和补偿。

### 2.5 重新打开条件

- 课程周期证明多个部署单元无法维护或演示环境无法稳定运行。
- 实际负载和故障边界不足以支持独立服务，合并可显著降低复杂度。
- 数据所有权无法在不引入大量跨服务事务的情况下成立。

## 3 D-12 A 只补齐 KMP 路线

### 3.1 决策内容

下一轮实验只验证 KMP 共享核心路线，不启动 Rust、Tauri Android 或 Qt 新实验。实验必须从现有 `android-minimal` 的纯 Kotlin/JVM 原型继续，不能把它直接称为已完成 KMP。

### 3.2 最小实验范围

- 将文档身份、同步状态机和数据契约放入真实 Kotlin Multiplatform shared module。
- Android 与 Windows 消费同一 source set 或同一版本化共享产物。
- 双端执行相同测试向量，验证序列化、错误语义和状态机一致性。
- Android 补齐 Android 12、release-like 构建和可审计证据。
- Windows 接入同一共享核心并保持分端 UI 和平台适配。

### 3.3 明确不包含

- 不验证共享 Rust 核心。
- 不验证 Tauri Android 整体应用。
- 不安装 Qt Android kit 或建设 Qt 双端工程。
- 不在 D-28 前宣布 KMP 为最终正式技术栈。

### 3.4 风险及验证

- 风险：现有 `kotlin.jvm` 模块迁移到 KMP 后出现依赖不兼容。
- 风险：Windows 和 Android 文档组件差异使共享范围小于预期。
- 验证：同一 DocumentIdentity、同步操作和冲突测试向量在双端通过。
- 验证：记录构建时间、依赖缓存、制品大小、共享职责和平台桥接量。

### 3.5 重新打开条件

- KMP 无法稳定完成双端构建或共享模块被平台依赖严重污染。
- 共享核心性能、运行时隔离或文档能力出现已测阻塞，并且 Rust 或 Qt 实验能回答明确问题。
- 项目负责人另行批准扩大实验范围。

## 4 D-13 A 保守冲突处理

### 4.1 决策内容

- 笔记并发编辑：不静默覆盖，保存当前版本和冲突副本。
- 阅读进度：采用服务端可信顺序确定的最新有效记录，不使用最大页码或设备本地时间作为唯一依据。
- 删除：使用带版本的 tombstone，拒绝旧设备基于删除前版本上传的修改。

### 4.2 技术要求

- `operationId`、`deviceId`、`itemId`、`baseRevision`、`currentRevision`、服务端序号和同步游标。
- 冲突副本保留来源设备、原基线版本、创建时间和关联文档版本。
- 进度只能在相同且有效的 DocumentIdentity 和 DocumentVersion 下比较。
- tombstone 保留期、设备确认和垃圾回收由 D-19、D-21 决定。

### 4.3 风险及验证

- 风险：用户看到重复笔记但缺少可理解的处理界面。
- 风险：长期离线设备在 tombstone 清理后重新提交旧操作。
- 验证：双端并发编辑、删除与编辑竞争、重复提交、乱序、时钟偏差和设备撤销。

### 4.4 重新打开条件

- 多设备并发频率明显高于个人低并发假设。
- 冲突副本数量和人工处理成本不可接受。
- 后续需求正式引入多人实时协作，需要字段级合并或 CRDT。

## 5 D-14 A 云中立部署基线

### 5.1 决策内容

正式架构以云中立能力描述部署单元、数据库、消息机制、密钥、日志和监控，不把业务代码绑定到特定云 SDK。同时提供华为云能力类别映射，用于课堂说明和后续部署验证。

### 5.2 云中立基线

- 容器或标准运行包承载粗粒度服务和工作进程。
- 关系数据库承载账号、同步、笔记、进度和最小元数据。
- 可选队列或数据库任务表承载异步工作，具体选择留给 D-30。
- HTTPS 入口、配置与密钥注入、结构化日志、指标、数据库迁移和备份恢复。
- 文档本体、解析结果和全文索引不进入服务端部署数据面。

### 5.3 华为云候选映射

| 云中立能力 | 华为云候选能力类别 | 状态 |
|---|---|---|
| 虚拟机或容器运行 | ECS 或 CCE | 候选映射，D-30/D-35 核对 |
| 关系数据库 | RDS | 候选映射，具体引擎待 D-30 |
| 消息或任务队列 | DMS 类消息能力或数据库任务表 | 是否需要独立中间件待 D-30 |
| 日志与监控 | LTS、监控/应用性能能力 | 字段和隐私边界待 D-32 |
| 密钥与秘密管理 | DEW/KMS 类能力 | 密钥边界待 D-31 |

### 5.4 风险及验证

- 风险：只写抽象组件而没有可复现部署证据。
- 风险：候选映射被误解为已经绑定具体云产品和规格。
- 验证：至少在一种干净环境完成部署、迁移、重启和备份恢复演练。
- 验证：将同一部署清单映射到华为云能力时，不改变服务和数据责任边界。

### 5.5 重新打开条件

- 课程明确要求以特定华为云产品作为正式运行基线。
- 实际演示环境只能稳定支持单机部署，且多单元部署无法复现。
- 某项必要能力无法通过云中立接口实现，必须接受供应商绑定。

## 6 D-15 A 单一模型供应方加内部适配器

### 6.1 决策内容

一期只接入一个外部模型供应方，通过项目内部 `ModelGateway/ModelAdapter` 隔离供应方 SDK、请求格式、流式响应、取消、限流和错误语义。具体供应方、模型和费用上限由 D-29 决定。

### 6.2 技术要求

- 客户端逐文件展示外发范围、服务类别和用途，并取得本次明确同意。
- 只发送经过权限过滤、版本校验和裁剪的最少证据。
- 适配器输出统一回答片段、完成状态、取消、超时、限流和安全拒绝错误。
- 业务层不得直接引用供应方 SDK 类型。
- 模型不可用时保留本地阅读、笔记和基础检索，并明确显示生成能力不可用。

### 6.3 风险及验证

- 风险：单一供应方故障导致在线生成整体不可用。
- 风险：适配器表面统一，实际仍依赖供应方特有语义。
- 风险：笔记摘录和证据属于敏感数据，外发和日志可能越界。
- 验证：用替换桩模拟超时、限流、断流、取消和供应方错误。
- 验证：静态检查业务模块不依赖供应方 SDK；数据流审计确认只发送最少证据。

### 6.4 重新打开条件

- 单一供应方稳定性、政策、费用或能力无法满足一期验证。
- 课程或实际环境要求离线、自托管或校内端点。
- 用户同意和数据政策允许并确有必要增加备用供应方。

## 7 决策组合后的约束

1. D-11 B 不要求客户端与服务端采用相同语言。
2. D-12 A 只控制下一轮实验范围，不等于 D-28 最终技术选择。
3. D-13 A 的规则应进入共享核心测试和服务端契约，但 tombstone 生命周期仍由 D-19/D-21 决定。
4. D-14 A 的华为云映射不改变本地文档和索引不进云的边界。
5. D-15 A 不允许业务层直接绑定模型供应方 SDK，也不允许自动向第二供应方回退。
6. AI/RAG 服务故障不得阻断身份同步；同步服务故障不得破坏两端本地阅读和笔记。

## 8 D-16 A 精确匹配与显式版本关联

### 8.1 决策内容

- 文件完整内容哈希相同，自动识别为相同 DocumentVersion。
- 内容哈希变化时建立新的 DocumentVersion，不因同名、同路径或相近大小自动绑定。
- 新版本只有在用户明确确认或从已有文档执行“登记新版本”时，才关联到原 DocumentIdentity。
- 文件名、Android URI 和 Windows 路径只作为本地展示或提示字段，不进入跨端身份主键。

### 8.2 技术要求

- 云端保存不可逆内容哈希、DocumentIdentity、DocumentVersion、版本关系和确认来源。
- 客户端必须支持错误关联撤销；撤销后不得删除原有笔记，只解除错误版本关系。
- 进度只在同一 DocumentVersion 下自动比较；跨版本迁移由 D-25 决定。
- 当前实验中的“同名即可能新版本”只能用于提示，不能自动建立关系。

### 8.3 风险及验证

- 风险：轻微编辑后需要用户确认，连续性低于组合指纹方案。
- 风险：用户可能错误确认版本关系。
- 验证：相同内容改名、同名不同内容、轻微编辑、重导出、错误绑定和解绑测试。

## 9 D-17 A 服务端可读的最小结构化同步

### 9.1 决策内容

云端可以保存结构化阅读进度、用户笔记正文、冲突副本和受长度限制的短摘录。使用传输加密、服务端存储加密、访问控制和日志脱敏保护。不得保存文件本体、完整解析结果、全文索引或可批量还原全文的摘录集合。

### 9.2 技术要求

- 字段至少包括账号、随机设备 ID、文档身份/版本、进度锚点、笔记、revision、operation id、游标和 tombstone。
- 摘录必须可关闭、受单条和累计范围限制，并记录来源 DocumentVersion。
- 本地路径、URI、令牌、密钥和原文正文不得进入日志。
- 字段字典、长度上限、备份保留和具体静态加密实现继续由 D-31 关闭。

### 9.3 风险及验证

- 风险：服务端泄漏会暴露笔记和短摘录。
- 风险：大量短摘录累计后形成可还原原文的数据集。
- 验证：样本载荷审计、累计摘录分析、越权测试、日志扫描、导出和删除核对。

## 10 D-18 A 自建个人账号和设备会话

### 10.1 决策内容

项目服务端自行管理个人账号、密码哈希、访问令牌、刷新令牌、随机设备 ID、设备会话、退出和设备撤销。不建设团队成员、组织、角色后台或独立管理员。

### 10.2 技术要求

- 密码采用适合密码存储的强哈希，不使用普通快速哈希。
- 访问令牌短期有效；刷新令牌轮换并支持重放检测。
- 用户可以查看并撤销设备；设备撤销后服务端拒绝旧令牌和后续同步。
- Android 和 Windows 凭据分别进入平台安全存储，不写入普通配置或同步载荷。
- 开放注册、邮箱验证和账号恢复的具体范围可按一期演示约束裁剪，但不得伪装为生产级完整身份系统。

### 10.3 风险及验证

- 风险：自建密码、令牌或恢复流程存在安全缺陷。
- 风险：设备退出被错误理解为远程清除本地文件。
- 验证：登录限速、令牌轮换、重放、密码修改、设备撤销、离线后重连和时钟偏差测试。

## 11 D-19 A 固定短期 tombstone 与异步硬删除

### 11.1 决策内容

- 删除立即对业务不可见并拒绝基于删除前 revision 的旧写入。
- tombstone 保留固定短期候选周期，期满后由异步任务硬删除。
- 具体保留天数、备份例外和传播阈值尚未决定，不能写成正式 SLA。
- 文件授权撤销、本地工作区移除、笔记删除、设备撤销、退出账号和删除账号保持不同语义。

### 11.2 技术要求

- tombstone 包含对象 ID、删除 revision、服务端删除序号和清理状态，不保存被删正文。
- 长期离线设备在 tombstone 过期后重连时必须接受游标失效或重新基线，不能直接重放旧操作。
- 清理任务应可重试、可观测，并记录不含敏感正文的最小审计。
- 账号删除需要单独的全局清理流程，不等同于普通笔记删除。

### 11.3 风险及验证

- 风险：固定周期过短会允许旧设备复活数据，过长会增加隐私和存储压力。
- 风险：备份恢复重新引入已删除数据。
- 验证：超过候选周期的离线设备、删除与编辑竞争、备份恢复、清理失败和重复删除测试。

## 12 D-20 A 分层本地存储与操作系统保护

### 12.1 决策内容

- 结构化文档元数据、进度和笔记进入本地数据库。
- 全文索引、解析结果、大型缓存和临时文件与业务数据库分层保存。
- 令牌和密钥必须进入 Android Keystore 或 Windows 对应的安全凭据能力。
- 一期不强制对整个本地工作区增加应用层加密，主要依赖应用沙箱、用户文件权限和操作系统磁盘保护。

### 12.2 技术要求

- 两端可以使用不同数据库和索引实现，但共享字段语义、迁移规则和测试向量。
- 文件授权撤销或移除文档时，解析结果、索引和缓存按生命周期清理。
- 敏感目录必须核对系统备份、卸载残留和崩溃转储行为。
- 若风险评审证明普通笔记或同步队列不能接受明文落盘，应重新打开 D-20 或在 D-31 增加选择性应用加密。

### 12.3 风险及验证

- 风险：设备已解锁、本地管理员、系统备份或文件复制场景下，笔记和索引可能可读。
- 风险：平台差异导致 Android 与 Windows 的清理和备份行为不一致。
- 验证：数据目录盘点、权限检查、数据库复制、系统备份、卸载残留、升级迁移和损坏恢复测试。

## 13 决策组合后的新增约束

1. D-16 A 要求同步服务把精确版本哈希与用户确认的逻辑文档关系分开保存。
2. D-17 A 允许服务端读取笔记和短摘录，因此 D-31 必须明确存储加密、访问控制、日志和备份边界。
3. D-18 A 增加自建身份安全责任，但不得扩展出团队角色与管理后台。
4. D-19 A 只选择生命周期策略，不确定具体保留天数。
5. D-20 A 不等于“无安全保护”；凭据安全存储、传输加密、权限和生命周期清理仍是强制要求。
6. D-21 A 通过绑定账号与 syncEpoch 的不透明游标处理 tombstone/游标过期；服务端返回 REBASE_REQUIRED，客户端重新基线时不得清空未确认的本地操作队列。

## 14 D-21 A 操作上传加账号级游标变更流

### 14.1 决策内容

- 客户端将每次离线写入先固化为不可变 `SyncOperation`，使用稳定 `operationId`、`deviceId`、`baseRevision` 和协议版本重复提交。
- 身份与同步服务先验证账号、设备会话和权限，再执行幂等、revision 与 D-13 冲突规则检查。
- 资源当前态、账号变更记录和该 operation 的稳定处理结果在同一事务中提交，避免“写入成功但没有可拉取变更”或重复副作用。
- 客户端通过账号级不透明 cursor 拉取增量变更；cursor 绑定账号和 `syncEpoch`，不能由客户端解析、拼接或跨账号复用。
- 本选择不要求 Kafka、RabbitMQ 或事件总线；一期可使用关系数据库变更表和单调序号实现变更流。

### 14.2 客户端状态机约束

1. 本地业务状态与待上传操作必须在设备崩溃后恢复；网络失败和响应丢失使用同一 `operationId` 重试。
2. 拉取结果应先按 revision 和 tombstone 规则安全落地，再原子保存新 cursor；在 cursor 提交前崩溃允许重复应用，但不得漏变更。
3. 服务端返回 `REBASE_REQUIRED` 时，客户端重建服务端可同步当前态与新 cursor；未确认本地操作队列保持不变，并在新基线上逐项重新校验。
4. 设备撤销、重新认证、永久校验失败和可重试错误必须进入不同状态，避免无限重试。

### 14.3 服务端与协议约束

- 同一账号内的变更记录具有稳定单调顺序，但不要求成为全系统事件总线或完整事件溯源日志。
- 幂等结果至少覆盖已应用、冲突副本、无变化、永久拒绝和可重试失败；响应丢失后的重复请求返回兼容结果。
- 删除写入 tombstone 变更；旧 revision 操作不得在删除传播后复活资源。
- 客户端和服务端声明协议版本；未知破坏性版本明确拒绝并提示升级，不得猜测字段语义。
- 实时推送、同步频率、batch limit、retry-after、版本支持周期和异常设备限流仍由 D-27、D-30、D-31 及实验决定。

### 14.4 风险及验证

- 风险：事务边界实现不完整导致状态与变更流分叉；验证数据库故障点和提交前后重试。
- 风险：错误推进 cursor 导致永久漏变更；验证拉取落地后、cursor 提交前的进程终止。
- 风险：重新基线误删本地待上传操作；验证长期离线、tombstone过期、旧操作重放和冲突副本生成。
- 风险：旧客户端误解新字段；验证支持版本、未知版本、可忽略字段和破坏性迁移。
- 现有 Android 最小实验只证明 operation id、持久化队列/cursor 和进程恢复的局部可行性，不证明真实服务端事务、身份认证、删除传播、Windows 对等或协议兼容。
