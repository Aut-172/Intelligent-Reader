## 1 ADR-011 至 ADR-021

ADR-011 至 ADR-021 的上下文、决定、后果和重新打开条件继承 V1.2。本版本不改变这些决定。D-19 的 tombstone 具体保留天数仍未确定；D-21 不要求 Kafka、RabbitMQ 或事件总线。

## ADR-022 分端成熟文档组件与统一能力合同

- 状态：Proposed
- 对应决策：D-22 A
- 上下文：Android 与 Windows 的文件权限、渲染栈和成熟组件不同，强行统一引擎会扩大工具链和兼容风险。
- 决定：两端分别使用平台原生或成熟文档组件；通过统一合同表达页面、坐标、文本范围、解析版本、OCR 来源、能力与降级。
- 正向后果：允许利用平台成熟能力，避免文档引擎成为共享核心前置条件。
- 负向后果：两端结果可能存在偏差，需要金标样本和合同测试维持等价语义。
- 验证：固定复杂 PDF 集合、扫描件、旋转、双栏、字体、bbox 高亮、OCR 和降级对照。
- 重新打开：任一平台无法稳定提供最低合同，或适配成本持续高于统一跨平台引擎的实测成本。

## ADR-023 客户端本地混合检索

- 状态：Proposed
- 对应决策：D-23 B
- 决定：客户端使用全文/BM25 与固定中文嵌入模型的混合召回和确定性融合；索引、向量和模型资产留在本地。
- 后果：提高同义问法召回并保持隐私；同时增加包体、首建索引、内存和跨端运行时成本。
- 约束：具体模型、索引库和融合权重属于实验参数；不得把索引上传云端。
- 验证：中文问法金标、关键词与语义对照、p50/p95、内存、磁盘、增量更新和损坏恢复。
- 重新打开：语义增益不足、资源超预算，或固定模型无法在两端稳定分发和运行。

## ADR-024 客户端完成证据选择与最少外发

- 状态：Proposed
- 对应决策：D-24 A
- 决定：客户端负责权限过滤、同意校验、检索、重排、裁剪和去重；服务端验证证据包后调用模型。
- 后果：最少化外发并避免云端拥有全文；客户端复杂度和双端一致性要求上升。
- 约束：网关不得主动访问客户端文件；撤权或拒绝的文档不得进入请求、缓存、日志或模型调用。
- 验证：网络抓包、服务端载荷审计、撤权竞态、越权构造和累计摘录分析。
- 重新打开：客户端资源不足以完成证据选择，且能证明替代方案不扩大隐私边界。

## ADR-025 双锚点引用与跨版本保守失效

- 状态：Proposed
- 对应决策：D-25 A
- 决定：引用保存结构锚点与字符锚点并绑定 DocumentVersion；跨版本默认 stale，不自动迁移。
- 后果：避免错误引用静默指向新内容；文档更新后用户需重新确认或重新生成。
- 约束：页面号不能作为唯一锚点；任何迁移必须显式、可追踪并保留置信度。
- 验证：重排、插页、删页、OCR 变化、解析器升级、新版本和旧版本缺失场景。
- 重新打开：stale 比例不可接受，且受控迁移算法能以批准的误判率通过金标。

## ADR-026 持久异步任务与数据库任务表

- 状态：Proposed
- 对应决策：D-26 A
- 决定：两端使用平台持久任务机制；服务端使用 PostgreSQL 任务表和 worker；事件仅用于状态与审计。
- 后果：基础设施少、事务和恢复直观；高吞吐与长任务隔离能力低于专用队列。
- 约束：任务需幂等、可取消、可重试，使用 lease 回收卡死执行；不建立通用事件总线。
- 验证：杀进程、重复领取、响应丢失、超时、取消、毒任务和数据库短暂不可用。
- 重新打开：数据库争用或吞吐在已验证负载下超限，且专用队列收益可测。

## ADR-027 REST/JSON、SSE 与轮询回退

- 状态：Proposed
- 对应决策：D-27 A
- 决定：普通请求采用版本化 REST/JSON，AI 增量输出采用 SSE，提供轮询最终结果回退；同步保持 push/pull 与不透明 cursor。
- 后果：契约易调试并适合课程部署；SSE 在代理、后台和弱网环境需专门恢复策略。
- 约束：错误模型、幂等、取消、超时、Retry-After、版本不兼容和未知字段行为必须明确。
- 验证：断流、重复片段、重连、代理缓冲、后台切换、轮询回退和旧客户端兼容。
- 重新打开：SSE 在目标环境无法稳定工作且轮询不能满足体验，或合同演进成本失控。

## ADR-028 KMP 共享业务核心

- 状态：Proposed，待实验关闭
- 对应决策：D-28 A
- 决定：KMP 共享领域、同步、合同、序列化和测试；UI、文档、文件、数据库、安全存储、后台任务和打包分端。
- 后果：关键状态机和合同可复用；Windows 目标、原生互操作和调试链路存在风险。
- 关闭门槛：Android 与 Windows 正式目标构建；同一测试向量通过；平台依赖未泄漏；桥接量、制品、构建与调试可接受。
- 重新打开：双端构建不稳定，共享核心被平台依赖污染，或共享收益低于维护成本。

## ADR-029 OpenAI Responses API 与固定模型快照候选

- 状态：Proposed，待正式 API 验证
- 对应决策：D-29 A
- 决定：通过内部 ModelAdapter 使用 OpenAI 官方 Responses API，候选快照为 `gpt-5.4-mini-2026-03-17`。
- 后果：可获得统一流式和结构化能力；受供应方政策、地区、配额、费用和模型生命周期影响。
- 约束：现有 Codex 使用证据不能替代应用 API；模型只接收授权最少证据；失败时降级到本地阅读与检索。
- 关闭门槛：正式项目账号完成可用性、数据政策、结构化输出、引用约束、取消、限流、质量和费用验证。
- 重新打开：候选模型不可用、政策不满足、质量或费用超出批准门槛。

## ADR-030 PostgreSQL 同步事务、变更流与任务表

- 状态：Proposed
- 对应决策：D-30 A
- 决定：PostgreSQL 同时承担同步事务、幂等结果、账号变更流和服务端任务表；一期不设通用缓存或消息代理。
- 后果：部署简单且可利用单库事务；需要控制表增长、索引、锁竞争、清理和备份恢复。
- 约束：资源状态、幂等结果和变更记录原子提交；任务重复执行不得产生第二次业务效果。
- 验证：真实数据库并发、故障点、死锁、清理、备份恢复、重复领取和重放。
- 重新打开：已验证容量下数据库无法满足事务、任务或保留需求。

## ADR-031 基础设施加密与平台安全凭据

- 状态：Proposed
- 对应决策：D-31 A
- 决定：TLS、基础设施静态加密、密钥/秘密管理、最小权限、平台安全凭据和日志脱敏构成一期安全基线；不增加业务字段应用层加密。
- 后果：实现和检索较直接；服务端与已解锁设备仍是需要保护的明文处理边界。
- 约束：秘密不得进入仓库、普通配置、日志和诊断包；备份与恢复环境遵循相同控制。
- 验证：威胁建模、权限审计、密钥轮换、秘密扫描、抓包、备份检查、日志与崩溃报告扫描。
- 重新打开：风险评审要求字段级或端到端加密，或平台保护无法满足目标。

## ADR-032 内容无关遥测与主动诊断包

- 状态：Proposed
- 对应决策：D-32 A
- 决定：记录最小结构化日志、指标和有限追踪；使用脱敏关联 ID；诊断包仅由用户主动导出。
- 后果：降低内容泄漏风险；故障定位可能需要用户复现和额外本地证据。
- 约束：不得记录正文、笔记、证据、令牌、完整路径或密钥；诊断包必须可预览和裁剪。
- 验证：故障注入后定位责任单元，同时执行内容与秘密扫描。
- 重新打开：无法用内容无关数据定位关键故障，且新增字段通过隐私评审。

## ADR-033 按文档复杂度分级的资源预算

- 状态：Proposed，待实验定值
- 对应决策：D-33 B
- 决定：文本型、复杂版式和扫描 PDF 分别设定时间、内存、磁盘、电量与降级预算。
- 约束：10 秒、30 秒、60 秒和 20 份文档是候选测量点，不是 SLA。
- 关闭门槛：双端固定样本报告 p50/p95、失败样本、资源峰值和降级结果，并批准正式阈值。
- 重新打开：复杂度分级不能预测成本，或同一等级内方差无法形成可执行验收。

## ADR-034 风险驱动的双端最小验证矩阵

- 状态：Proposed
- 对应决策：D-34 A
- 决定：使用覆盖共享核心、文档、检索、RAG、引用、任务、通信、同步、安全、诊断、性能与部署的双端最小矩阵。
- 后果：验证范围与风险直接对应；需要维护金标、故障注入和可追踪证据。
- 约束：单端、桌面脚本或候选代码不能代替正式目标证据。
- 重新打开：矩阵无法覆盖高风险路径，或执行成本超过课程周期且需正式裁剪。

## ADR-035 条件式最小部署基线

- 状态：Proposed，未最终冻结
- 对应决策：D-35 A
- 决定：三个逻辑责任单元允许同机部署，共用 PostgreSQL 与数据库任务表；保持云中立能力描述。
- 后果：降低课程部署成本，同时保留逻辑故障边界；同机资源争用与单点故障需要验证。
- 关闭门槛：关键 ADR 验证完成或风险被接受；D-33、D-34 关闭；干净环境重建、迁移、重启、备份恢复通过；一致性评审通过。
- 重新打开：同机部署无法满足故障隔离或资源预算，或课程明确要求独立云部署单元。
