## 7 可能的答辩问题与建议回答

| 问题 | 建议回答要点 |
|---|---|
| 为什么不用纯微服务？ | 团队与课程周期不支持细粒度运维成本；当前用三个粗粒度责任单元保留隔离和后续拆分点。 |
| 为什么不把文档和索引放云端？ | 本地优先、隐私和版权是核心驱动；全文和索引不上传，服务端只保存最小同步数据。 |
| 既然有三个逻辑单元，为何可以同机？ | 逻辑责任和物理部署分离；一期先验证边界和恢复，资源/隔离证据不足时再拆节点。 |
| Android 与 Windows 为什么不用同一 UI？ | 文件、渲染、后台、安全存储和安装差异显著；共享稳定核心比强行共享 UI 风险更低。 |
| KMP 已经确定了吗？ | 方向已选但 ADR 仍 Proposed；必须完成真实 Android/Windows targets 同源构建和测试。 |
| AI 为什么由客户端检索？ | 客户端掌握权限、同意、版本和全文索引，能证明最少证据外发；网关只校验和调用模型。 |
| 如何保证引用可靠？ | 引用绑定文档版本、解析器版本、结构与字符锚点；跨版本默认 stale，不静默迁移。 |
| 同步如何避免重复和漏数据？ | 不可变 operation、幂等结果、revision、账号级变更记录和 cursor；失效时 REBASE 并保留未确认操作。 |
| 为什么不用消息队列？ | 当前任务量和一致性可先由 PostgreSQL 任务表、lease 和幂等承担；只有瓶颈证据出现后再评估。 |
| OpenAI 方案是否已经验证？ | 目前只有适配模式和合成证据；正式 API、政策、质量、费用和限流未关闭，仍是候选。 |
| 10/30/60 秒是不是 SLA？ | 不是，只是候选测量点；正式阈值必须基于双端、三类文档、p50/p95 和资源数据。 |
| 如何处理 OCR 失败？ | 能力合同记录来源、置信度和降级原因；失败时退到页面级阅读/引用，不伪造精确文本坐标。 |
| 如何保护日志隐私？ | 只允许内容无关白名单字段，禁止正文、笔记、证据、令牌和完整路径，并执行内容扫描。 |
| 当前最大的未决风险是什么？ | Windows 正式证据、KMP 双端、正式模型 API、真实同步/PostgreSQL、性能阈值和正式图件。 |
| 哪些情况会重开架构决策？ | 技术验证形成明确否定证据，例如统一文档合同失败、未授权外发、KMP 不可维护或同机部署无法满足隔离。 |

## 8 视觉与证据规则

1. 每张架构图显示 `Proposed` 或验证状态，不使用“最终”字样。
2. 一页只表达一个主要观点，避免把业务能力、进程和部署节点混画。
3. 平台结果页标注设备、系统版本、构建类型、样本和证据等级。
4. 未完成项使用“待 B/C/D/实验/评审”，不得用空白或绿色勾选掩盖。
5. 所有数字注明“实测”“候选测量点”或“未定”，不混用。
6. 正式 PPT 制作前检查 37、38 和 40 的问题/提交门禁。
