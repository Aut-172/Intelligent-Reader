## 1 项目背景和正式范围

智能阅读器一期面向 Android 12+ 与 Windows 11 个人用户，提供本地文档导入、阅读、笔记、本地检索、基于授权证据的 AI 问答以及个人账号下的跨设备同步。项目采用本地优先边界：文档本体、解析结果、OCR 结果、全文索引和向量索引保留在用户设备；服务端只处理账号、设备会话、最小文档标识、进度、笔记、冲突副本、同步操作、变更记录、任务状态和内容无关审计信息。

一期不包含 Web 正式客户端、团队工作区、公开分享链接、独立管理员产品、云端全文索引或由服务端主动抓取本地文件。课程材料中的“分享”解释为用户主动导出；“管理后台”解释为受限运维、审计和任务观察能力。

## 2 架构驱动因素

| 驱动因素 | 对架构的主要影响 | 关联决策 |
|---|---|---|
| 本地优先与隐私最少化 | 文档、索引和证据选择留在客户端；外发需逐次授权 | D-17、D-20、D-23、D-24、D-31 |
| Android 与 Windows 双端 | 平台能力分端实现，共享核心只承载稳定领域和合同 | D-12、D-22、D-28 |
| 离线可用与弱网韧性 | 阅读、笔记和检索不依赖云端；同步与 AI 可恢复、可降级 | D-13、D-21、D-26、D-27 |
| 引用正确性 | 文档版本、解析器版本和双锚点共同约束引用；跨版本默认 stale | D-16、D-25 |
| 课程周期和团队能力 | 避免细粒度微服务、通用事件总线和过早云产品绑定 | D-11、D-14、D-30、D-35 |
| AI 供应方不确定性 | 使用 ModelAdapter 隔离正式 API、错误、限流和替换 | D-15、D-29 |
| 可验证与可追踪 | 每项 Proposed ADR 必须对应风险驱动的双端证据 | D-33、D-34、D-35 |

## 3 产品、平台和课程约束

1. 产品边界是个人阅读与个人同步，不扩展为协作知识库。
2. Android 最低目标为 Android 12+；Windows 目标为 Windows 11。
3. 两端允许使用不同成熟文档组件，但必须提供统一能力合同和显式降级。
4. KMP 是共享领域、同步、合同和测试的候选实现，不共享 UI、文件系统、数据库、文档引擎、安全存储和安装系统。
5. 服务端数据最少化，不保存文档本体、解析结果、全文索引或向量索引。
6. AI 只接收客户端授权和裁剪后的最少证据，不得绕过 ModelAdapter。
7. 一期优先少量粗粒度责任单元，可在同一节点部署，但不把逻辑单元等同为独立微服务。
8. 10 秒、30 秒、60 秒和 20 份文档仅为候选测量点，不是正式 SLA。
9. D-19 tombstone 保留天数、D-29 费用上限和 D-33 性能阈值仍需定值。

## 4 分层架构调研

分层架构适合把界面、应用编排、领域规则、平台适配和基础设施分开，使 Android 与 Windows 在共享概念的同时保留平台实现差异。其优势是职责清晰、便于单元测试和替换基础设施；风险是仅按技术层切分可能形成跨层修改链和“万能服务层”。

本项目采用“分层加能力边界”的方式：客户端区分 UI/交互、应用编排、共享领域候选、平台适配和本地基础设施；服务端按身份同步、AI/RAG、任务审计划分逻辑责任。分层用于依赖方向，业务能力用于组织责任，两者不互相替代。

## 5 模块化单体和少量粗粒度服务调研

模块化单体通过明确模块边界、内部端口和数据所有权降低部署复杂度；少量粗粒度服务则在需要独立故障边界、外部网络入口或异步执行时提供隔离。本项目的身份与同步、AI/RAG、任务与审计具有不同的安全、故障和资源特征，因此保留三个逻辑责任单元；课程一期允许同机部署，并共同使用 PostgreSQL。

该方向最符合团队规模与课程周期，但必须防止形成分布式单体：跨单元调用应通过版本化合同，数据库表的写入责任要明确，worker 不得直接拥有同步事务，AI 网关不得读取客户端文件。

## 6 经典微服务架构调研

经典微服务有利于独立扩缩容、独立发布和故障隔离，但会引入服务发现、分布式追踪、网络重试、版本兼容、数据一致性和部署运维成本。课程列出的认证、文档、解析、索引、阅读、AI、检索、分享、调度和管理能力不应逐项自动变成微服务。

一期不采用细粒度微服务。只有当真实容量、团队并行发布、故障隔离或合规边界形成明确证据时，才考虑从粗粒度单元中拆分。拆分必须基于数据所有权和独立变化率，而不是目录或功能名称。

## 7 事件驱动架构调研

事件驱动架构适合松耦合通知、异步扩展和审计，但会增加投递语义、重复消费、顺序、补偿和可观测性复杂度。当前同步需要的是不可变 SyncOperation、账号级变更记录和不透明 cursor；服务端任务需要 PostgreSQL 任务表、lease、重试和幂等。

一期不引入 Kafka、RabbitMQ 或通用事件总线。状态变化可以形成审计事件或通知，但业务正确性由数据库事务、幂等键和持久任务状态保证。只有测量证明 PostgreSQL 方案成为瓶颈时才重新评估专用消息基础设施。

## 8 本地优先架构调研

本地优先能保证离线阅读、减少敏感数据外发并降低云端存储成本，但要求客户端承担文档处理、索引、冲突、持久任务和数据生命周期管理。跨设备同步不能简单采用最后写入覆盖，否则会造成笔记丢失、删除复活或进度回退。

本项目采用客户端本地全文和向量索引、不可变操作上传、账号级 revision/cursor、保守冲突副本和 tombstone。服务端保存最小结构化数据并在同一事务中更新当前态、幂等结果和变更记录。D-19 的 tombstone 周期仍需结合长期离线和隐私要求评审。

## 9 RAG 架构调研

RAG 的关键不是增加一个“AI 服务”，而是保证检索证据的权限、版本、引用和最少外发。项目拟采用客户端本地 BM25/全文与固定中文嵌入混合检索；客户端完成权限校验、用户同意、版本校验、重排、去重和裁剪；AI/RAG 网关只校验证据合同、执行限制并调用模型适配器。

引用绑定 DocumentIdentity、DocumentVersion、ParserVersion、结构锚点和字符锚点。跨版本默认 stale。模型生成内容只能引用证据白名单，供应方超时、限流或不可用时降级到本地检索或非生成式结果。

## 10 Android 和 Windows 平台调研摘要

### 10.1 Android

主分支 `219a2f2` 已补充 A-E01、02、06、10、12、13、15：真实 KMP `androidTarget + jvm` 使用 `commonMain/commonTest`，debug/release 单元测试各 16/16；七类 PDF 的文本、bbox、页码、阅读顺序和锚点达到 Android 侧最低合同；内容变化可标记 stale；Keystore、备份排除和日志最小化通过；签名 release 完成安装、升级、卸载；clean 后可重建。证据仍只覆盖一台 Android 15 高端设备，未覆盖 Android 12、OCR、中文嵌入、真实网络/后端、正式 p50/p95 和另一台干净机器。它们提升了 Android 侧 E2/E3 成熟度，但不能替代 Windows 或关闭双端/系统级 ADR。

### 10.2 Windows

截至本稿，角色 B 尚未提交正式 B-D01 至 B-D06 平台调研报告。仓库外/未跟踪实验工作树中存在基于旧提交的 Compose/JVM、PDFBox/PDF.js 或坐标相关候选材料，只能登记为 Candidate Evidence，不能作为 Windows 正式事实，也不能替代 Windows 11 干净环境、安装打包、安全存储、后台任务和真实文档金标验证。

### 10.3 跨端结论

Android 与 Windows 证据不得互相替代。跨端可共享的是稳定领域模型、同步状态机、合同、序列化与测试向量；文档组件、文件访问、数据库、安全存储、后台任务、UI 和打包必须保留平台责任。

## 12 当前拟议组合架构

当前方向是“客户端分层 + 本地优先 + 客户端 RAG + KMP 共享核心候选 + 少量粗粒度服务/工作进程 + PostgreSQL 事务与任务表”。

1. Android 和 Windows 客户端分别负责文档、OCR、本地索引、阅读笔记、证据选择、持久任务和平台安全能力。
2. KMP 候选只共享领域、同步、合同、序列化和测试，不共享 UI 或平台基础设施。
3. 身份与同步单元负责个人账号、设备会话、最小同步数据、幂等、revision、cursor 和 tombstone。
4. AI/RAG 网关负责证据合同、限制、ModelAdapter、SSE/轮询和错误归一化。
5. 任务与审计 worker 负责数据库任务领取、重试、清理和内容无关审计。
6. 三个逻辑责任单元可在一期同一节点部署；PostgreSQL 保存服务端最小数据和任务状态。

## 13 未采用方案及理由

| 方案 | 一期不采用原因 | 可能重新评估条件 |
|---|---|---|
| 每项课程能力一个微服务 | 超出团队与课程周期，产生分布式单体风险 | 独立扩缩容、发布或合规边界有真实证据 |
| 云端全文索引/向量库 | 违反本地优先、隐私和版权边界 | 产品范围和用户授权模型正式变化 |
| 通用消息中间件 | 当前 PostgreSQL 事务与任务表尚未证明不足 | 实测容量或隔离要求超过数据库方案 |
| 跨端统一 UI/文档引擎 | 平台文件、渲染、后台和打包差异大 | 双端实验表明总成本显著更低且能力不退化 |
| 跨版本自动迁移引用 | 可能产生静默错误引用 | 有受控迁移金标、置信度和可追踪回滚机制 |
| 多模型供应方并行 | 增加质量、费用和错误语义治理成本 | 单供应方政策、质量或可用性不满足门槛 |
| Web 客户端、团队空间、公开分享 | 不属于一期产品范围 | 需求基线和权限模型正式变更 |

## 15 风险、假设和后续验证

1. Android KMP 边界已得到局部支持，但 Windows 正式客户端消费、打包、调试和双端维护成本仍可能使 D-28 失败。
2. Windows 文档、文件访问、任务、安全存储和安装证据缺失，需 B 提交正式报告。
3. Android 最低版本、release-like 构建、复杂文档和资源预算尚未覆盖。
4. 混合检索的语义增益可能不足以抵消模型包体、内存和索引成本。
5. AI 正式 API 的区域、留存、训练使用、限流、费用和模型快照可用性未关闭。
6. 同步协议可能在长期离线、时钟偏差、删除竞争和游标失效下出现遗漏或复活。
7. tombstone 具体天数、备份例外和账号删除周期未确定。
8. 同机部署可能出现资源争用；需干净部署、重启、迁移和恢复证据。
9. 遥测和诊断可能意外包含正文、路径或秘密；必须采用白名单和内容扫描。
10. 任一否定证据应触发替代实现或重新打开建议，角色 A 不单独改变决策。

## 16 架构选型结论及适用边界

当前最适合一期的不是单一架构风格，而是受边界约束的组合：以分层和模块化控制代码依赖，以本地优先保护内容与离线能力，以客户端 RAG 保证权限和最少外发，以少量粗粒度服务隔离同步、AI 和异步任务，以 PostgreSQL 提供事务、变更流和任务恢复。

该结论适用于个人用户、Android 12+、Windows 11、有限课程周期、单一外部模型候选和中低并发服务端。它不自动适用于团队协作、公开分享、云端全文知识库、大规模多租户、细粒度独立发布或强实时协同场景。D-11 至 D-35 在证据与评审门槛关闭前均保持 Proposed，本报告不得作为 Accepted 或最终部署冻结的替代批准。
