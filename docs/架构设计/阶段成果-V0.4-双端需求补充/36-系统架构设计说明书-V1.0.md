# 智能阅读器系统架构设计说明书

- 版本：V1.0
- 日期：2026-11-17
- 负责人：角色 A（集成）；角色 D 负责正式图件
- 状态：Proposed 评审草稿；文字视图已集成，正式图件待角色 D
- 依据：22 V1.6、23 V1.3、24 V1.3、25 V1.3、29 V1.0、33 V1.0、34 V1.0、35 V1.0
- 解释限制：本文件不将逻辑单元自动等同为独立进程或独立部署服务

## 1 文档目的和范围

本说明书定义智能阅读器一期的架构目标、责任边界、数据边界、通信、部署、质量属性和验证门槛。范围包括 Android、Windows、共享核心候选、服务端最小能力、外部模型适配和 PostgreSQL；不包含 Web 正式客户端、团队工作区、公开分享链接或独立管理员产品。

## 2 架构目标

1. 让阅读、笔记和本地检索在离线时仍可用。
2. 让文档本体、全文索引和向量索引默认留在客户端。
3. 让 Android 与 Windows 保持平台质量，同时共享稳定领域规则与测试。
4. 让同步无静默丢失、重复副作用和删除复活。
5. 让 AI 只使用用户授权的最少证据，并可追踪引用。
6. 在课程周期内保持部署、测试和运维复杂度可控。

## 3 架构约束

- Android 12+ 与 Windows 11 是一期正式客户端范围。
- D-11 至 D-35 方向已选，但 ADR 仍为 Proposed。
- 文档处理和本地索引是客户端责任，不上移到云端。
- KMP 共享核心候选不得依赖 UI、文件、数据库、文档 SDK、安全存储和后台任务类型。
- 模型调用必须经过 ModelAdapter；正式 API 结论需 D-29 验证。
- 一期不默认引入 Kafka、RabbitMQ、Redis 或通用事件总线。
- 三个逻辑服务单元可同机部署；最终部署仍受 D-35 门槛约束。

## 5 架构原则

1. 本地优先，云端最少。
2. 平台能力分端，稳定规则共享。
3. 先定义合同和失败语义，再选具体库。
4. 逻辑责任、进程和部署单元分别建模。
5. 事务、幂等和持久状态优先于隐式时序假设。
6. 引用宁可显式 stale，不静默迁移到错误内容。
7. 遥测默认不含内容、秘密和完整路径。
8. 证据不足时维持 Proposed，不以方向选择代替验证。

## 6 系统上下文

系统外部参与者包括个人用户、Android/Windows 文件与安全平台、OpenAI 候选模型服务、云基础设施和课程评审者。用户在本地选择文件并授权；客户端完成解析、索引、阅读、笔记和证据选择；身份同步单元交换最小结构化数据；AI/RAG 网关把已授权证据交给模型适配器；任务与审计 worker 处理可恢复后台任务。

正式系统上下文图待角色 D 提交。图中不得出现 Web 正式客户端、团队空间、公开分享或云端文档库。

## 7 逻辑分层

| 层次 | 客户端责任 | 服务端责任 |
|---|---|---|
| 表现与交互 | 阅读器、笔记、权限与同意、冲突/stale/降级提示 | 无独立管理产品；仅受限运维接口候选 |
| 应用编排 | 导入、解析、索引、检索、问答、同步、任务恢复 | 身份、同步、AI 请求、任务与审计用例 |
| 领域与合同 | DocumentIdentity/Version、引用、同步状态、公共 DTO | 资源规则、幂等、错误合同、模型适配合同 |
| 平台适配 | 文件、文档组件、OCR、数据库、安全存储、后台任务 | HTTPS、PostgreSQL、秘密、日志指标、模型 SDK |
| 基础设施 | 本地数据库、索引、缓存、模型资产 | 计算节点、PostgreSQL、备份、监控与密钥能力 |

## 8 业务能力划分

一期业务能力包括：个人身份与设备、文档导入与阅读、阅读进度、笔记、文档内检索、授权 AI 问答、引用回跳、个人同步、主动导出、任务恢复和诊断导出。业务能力描述用户价值，不代表代码包、进程或微服务。

## 9 模块、组件和部署单元映射

| 课程/业务能力 | 逻辑模块 | 代码组件候选 | 运行进程 | 独立部署服务 |
|---|---|---|---|---|
| 认证与权限 | 身份、设备会话、授权策略 | Auth/Session 模块 | 身份与同步进程内 | 否；并入身份与同步单元 |
| 文档与阅读 | 文档适配、阅读、进度、笔记 | 两端平台模块 + 共享领域接口 | 客户端进程 | 否，完全端侧 |
| 解析与 OCR | 文档组件/OCR 适配 | Android/Windows adapter | 客户端进程/平台任务 | 否，完全端侧 |
| 索引与检索 | BM25/全文、向量、融合、重排 | 两端本地检索组件 | 客户端进程/平台任务 | 否，完全端侧 |
| AI 问答 | 证据合同、模型适配、流式结果 | 客户端证据组件 + 网关组件 | 客户端 + AI/RAG 进程 | 是/可同机的粗粒度单元 |
| 同步 | operation、revision、cursor、冲突、tombstone | shared 候选 + 服务端同步模块 | 客户端 + 身份同步进程 | 是/可同机的粗粒度单元 |

| 管理后台 | 受限运维、审计、任务观察 | 运维端点/脚本 | 现有服务进程内或受限工具 | 否，不扩展独立产品 |

## 10 Android 客户端责任

负责 SAF 文件授权与重绑、Android 文档/OCR 适配、本地数据库和索引、阅读与笔记 UI、本地证据选择、可靠持久任务、Keystore 凭据、同步 operation/cursor、主动诊断包和应用生命周期适配。不得把 Android URI、SDK 类型或后台机制泄漏到共享核心。

## 11 Windows 客户端责任

负责 Windows 文件选择与权限、文档/OCR 适配、本地数据库和索引、阅读与笔记 UI、本地证据选择、Windows 可靠任务宿主、Credential Manager/DPAPI、安装与更新、同步 operation/cursor 和主动诊断包。正式事实待角色 B 的 Windows 11 干净环境报告。

## 12 共享核心责任

KMP 共享核心候选包括领域模型、DocumentIdentity/Version、同步状态机、冲突规则、公共合同、序列化和测试向量。它不负责 UI、文件句柄、路径/URI、文档组件、本地数据库、安全存储、网络 SDK、后台任务和安装系统。D-28 只有在真实 KMP Android/Windows target 同源构建和测试通过后才能关闭。

## 13 服务端责任

服务端由三个逻辑责任单元组成：身份与同步、AI/RAG、任务与审计。它们可以是同一代码库中的清晰模块、同一主机上的多个进程或后续独立部署服务；本文件不预先固定最终物理拆分。

## 14 文档处理责任

文档解析、渲染、页面图像、文本定位和 OCR 由两端成熟组件承担。统一合同至少包括 `DocumentPage`、`TextRange`、`NormalizedRect`、`ParserVersion`、`CapabilitySet` 和 `DegradationReason`。OCR 必须标记来源、语言、置信度和页面范围，不能与原生文本静默混合。

## 15 本地索引和混合检索责任

客户端构建全文/BM25 与固定中文嵌入向量索引，索引绑定 DocumentVersion 和 ParserVersion。检索流程包括权限过滤、候选召回、融合、重排、去重和资源裁剪。具体索引库、嵌入模型、运行时和权重仍属于实验参数。

## 16 RAG 和模型适配责任

客户端生成带版本、锚点、摘要、权限和同意证明的证据包。AI/RAG 网关验证合同、大小、幂等、取消和错误语义，通过 ModelAdapter 调用 Responses API 候选。供应方类型不得进入业务合同，模型不得自行读取客户端文件，引用只能来自证据白名单。

## 17 同步协议和状态机

1. 客户端原子保存业务变化与不可变 SyncOperation。
2. push 请求包含 operationId、baseRevision、syncEpoch 和协议版本。
3. 服务端校验设备会话、权限、幂等、revision 和 tombstone。
4. 同一 PostgreSQL 事务更新资源当前态、幂等结果和账号变更记录。
5. pull 使用不透明 cursor；客户端幂等应用后保存新 cursor。
6. cursor/保留窗口失效返回 REBASE_REQUIRED，客户端保留未确认操作。
7. 笔记冲突生成冲突副本；进度按可信顺序处理；删除通过 tombstone 传播。

## 18 异步任务机制

Android 与 Windows 使用各自可靠的持久任务机制。服务端任务表记录状态、attempt、nextRunAt、leaseOwner、leaseUntil、idempotencyKey 和 lastErrorClass。worker 采用幂等领取、lease 回收、有限重试、取消和毒任务隔离。业务副作用与任务状态分离，重复执行不得产生第二次业务效果。

## 19 数据边界

| 数据类别 | 客户端 | 服务端 | 模型供应方 |
|---|---|---|---|
| 文档本体、页面图像、OCR、解析结果 | 保存 | 禁止 | 禁止整体发送 |
| 全文/BM25、向量索引、嵌入资产 | 保存 | 禁止 | 禁止 |
| 路径、URI、平台句柄 | 平台层保存 | 禁止 | 禁止 |
| 账号、设备会话 | 最小缓存 | 保存 | 禁止 |
| DocumentIdentity/Version、不可逆哈希 | 保存 | 最小保存 | 仅必要时脱敏引用标识 |
| 进度、笔记、冲突副本、受限短摘录 | 保存 | 按同步范围保存 | 仅本次授权证据 |
| operation、revision、cursor、tombstone、任务状态 | 保存/交换 | 保存 | 禁止 |
| 日志、指标、追踪 | 内容无关 | 内容无关 | 供应方政策待验证 |

## 20 信任边界

信任边界位于：本地文件与应用、应用与本地第三方组件、客户端与服务端、服务进程与 PostgreSQL、AI 网关与模型供应方、运维人员与生产数据。每次跨边界必须有最小权限、输入验证、版本合同、内容限制和脱敏规则。逐文件同意、撤权、证据裁剪和日志白名单是 AI 外发边界的核心控制。

## 21 主要接口和通信方式

| 接口 | 方式 | 关键语义 |
|---|---|---|
| 客户端—身份同步 | HTTPS REST/JSON push/pull | access token、设备会话、幂等、revision、cursor、版本 |
| 客户端—AI/RAG | HTTPS REST/JSON + SSE | 最少证据、取消、超时、Retry-After、轮询回退 |
| AI/RAG—模型供应方 | ModelAdapter + Responses API 候选 | 错误归一、结构化输出、流式、引用白名单 |
| worker—PostgreSQL | 事务 + lease | 幂等领取、恢复、清理、审计 |
| 平台层—共享核心 | 版本化端口/数据合同 | 禁止平台对象进入 shared |

SSE 中断后不得拼接不确定片段；客户端通过请求 ID 查询最终结果。同步和 AI 协议必须定义未知字段、版本不兼容、限流和取消行为。

## 22 部署架构

拟议部署包含 Android 应用、Windows 应用、HTTPS 入口、身份与同步进程、AI/RAG 网关进程、任务与审计 worker、PostgreSQL、内容无关可观测性和秘密注入。三个服务端逻辑单元允许部署在同一计算节点，后续可依据资源与隔离证据拆分。

正式云中立部署图、故障路径图和节点规格待角色 D 与部署验证回填。门槛满足前不得标注为 Final。

## 23 华为云能力映射

| 云中立能力 | 华为云候选能力 | 约束 |
|---|---|---|
| 计算节点/容器 | ECS 或 CCE | 仅能力映射，不绑定代码或最终产品 |

## 24 可用性和故障降级

- 云端不可用：本地阅读、笔记和检索继续；同步操作留在持久队列。
- 模型不可用/限流：显示明确状态，回退本地检索或稍后轮询，不伪造回答。
- SSE 中断：取消不确定流，查询最终结果或重试，不重复片段。
- OCR/解析失败：记录能力和降级原因，允许页面级阅读或人工选择。
- 索引损坏：从文档和解析结果重建，不上传索引。
- cursor 失效：进入 REBASE_REQUIRED，保留未确认本地操作。
- worker 崩溃：lease 到期后恢复，幂等键阻止重复副作用。

## 25 安全、隐私和版权

使用 TLS、基础设施静态加密、秘密管理、最小权限、Android Keystore、Windows Credential Manager/DPAPI 和日志脱敏。文档、笔记和证据遵循最小收集与逐次授权；主动导出不等同公开分享；模型供应方的区域、留存、训练使用和删除政策必须在 D-29 正式核验。若威胁评审要求字段级加密或 E2EE，应提出重新打开 D-31/D-17，而不是降低要求。

## 26 可观测性

只采集内容无关的状态、耗时、错误类别、重试计数、版本和脱敏关联 ID。禁止记录正文、笔记、证据、访问令牌、完整路径和供应方秘密。客户端诊断包由用户主动生成，默认可预览、可裁剪且不自动上传。指标应能区分文档适配、索引、同步、AI 网关、模型供应方和 worker 责任单元。

## 30 风险和后续演进

当前高风险是 Windows 正式证据缺失、真实 KMP 双端目标未完成、Responses API 正式验证缺失、同步/PostgreSQL 故障路径未验证、D-19 周期未定和 D-33 阈值未定。角色 D 还需提交当前边界下的系统上下文、逻辑、组件、运行单元、云中立部署、华为云映射、文档到回答数据流、同步/RAG 时序、任务状态、信任边界及故障降级图。

后续演进应由证据触发：容量不足时才评估拆服务或消息代理；共享收益不足时才重新打开 KMP；模型政策或费用失败时才替换供应方；团队协作或公开分享只有在需求基线正式变化后进入架构。任何演进均需更新决策、ADR、视图、验证和提交索引。
