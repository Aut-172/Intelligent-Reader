# 智能阅读器架构阶段第三批待决策项详细比较

- 版本：V1.0
- 日期：2026-11-17
- 状态：Decision Input / Research Question
- 决策范围：D-16 至 D-21
- 上游决策：D-11 B、D-12 A、D-13 A、D-14 A、D-15 A
- 决策人：当前对话人

## 1 文档目的

本文将数据与同步边界的六项研究问题转换为可集中选择的架构方案。每项均比较收益、可行性、实施难度、技术需求、与现有决策的兼容性、风险及验证方法。本文不替项目负责人选择方案，也不把现有实验自动升级为正式架构决定。

本批选择完成前，不确定以下内容：

1. 文档身份和版本的最终匹配算法。
2. 云端同步载荷的字段、摘录长度和加密方式。
3. 正式登录、设备会话和账号恢复实现。
4. tombstone 保留期、恢复窗口和硬删除条件。
5. 两端本地数据库、索引、缓存和应用层加密边界。
6. 正式同步接口、游标失效和协议兼容规则。

## 2 当前证据与证据限制

### 2.1 已有正向证据

当前 Android 最小工程和共享 Kotlin 代码已经提供以下候选证据：

- 可以在不上传全文的情况下计算文件 SHA-256，并用规范化文件名和文件大小保存辅助元数据。
- 可以区分内容完全相同、同名但内容变化和不同文档三种候选匹配结果。
- 可以用 `operationId`、`deviceId`、`itemId`、`baseRevision` 和 `cursor` 表达最小同步操作。
- 离线操作队列和同步游标可以持久化，并在进程被终止后恢复。
- 同一 `operationId` 可以避免客户端重复入队；瞬时失败可以留队重试。
- 可以表达笔记冲突副本、进度版本比较和删除优先的 tombstone 规则。

### 2.2 尚未形成的证据

现有代码尚未验证：

- 文件重排版、重导出、扫描 OCR、轻微编辑后的可靠版本关联。
- 真实服务端的幂等、事务、批次部分成功和游标过期。
- 真实账号、访问令牌、刷新令牌、设备撤销和账号恢复。
- Android Keystore、Windows 凭据安全存储或本地数据库加密。
- 笔记正文、原文摘录和同步队列的隐私分级与加密。
- tombstone 保留、设备确认、备份清理和长期离线设备复活防护。
- Android 与 Windows 对同一同步协议和状态机的双端验证。

因此，以下方案比较以现有实验作为可行性证据，不把它视为最终实现承诺。

## 4 D-16 文档身份与版本匹配策略

### 4.1 必须区分的概念

- `DocumentIdentity`：用户语义上的同一份文档，例如某本教材或某份报告。
- `DocumentVersion`：特定字节内容和解析结果对应的不可变版本。
- 文件授权：设备对本地文件的访问能力，不等于文档身份。
- 匹配置信度：只能作为提示或门禁，不能把低置信结果自动绑定。

不同 `DocumentVersion` 的进度、引用和笔记锚点不得直接覆盖。文件路径、Android URI、Windows 路径和文件名都不能单独作为跨端身份。

### 4.2 方案 A 精确内容哈希自动匹配，版本变化显式关联

规则：内容哈希相同则自动认定为相同 `DocumentVersion`；内容变化时创建新版本，只有用户明确确认或从已有版本执行“登记新版本”才关联到原 `DocumentIdentity`。同名只用于提示，不用于自动绑定。

- 收益：误绑定风险最低；规则可解释；云端只需要哈希和少量元数据。
- 可行性：高。现有实验已验证 SHA-256 和精确匹配的最小实现。
- 实施难度：低到中。主要增加显式关联、解绑和版本迁移界面。
- 技术需求：完整内容哈希、随机文档 ID、不可变版本 ID、版本父子关系、人工确认记录和解绑审计。
- 兼容性：与 D-05、D-13 A 和本地优先高度兼容；不要求上传全文。
- 风险：同一文档轻微修改后不能自动延续进度；用户可能错误确认版本关系。
- 验证：相同内容改名、跨路径复制、同名不同内容、轻微编辑、重新导出和错误解绑测试。

### 4.3 方案 B 组合指纹和置信度匹配

规则：内容哈希相同为精确匹配；内容不同时，结合规范化文件名、大小、页数、标题结构、稳定分段指纹或局部哈希计算置信度。高置信结果可提示快速确认，中低置信结果必须保持独立。

- 收益：可识别重命名、重导出或轻微修改后的候选新版本，跨端连续性更好。
- 可行性：中。普通文本和结构化 PDF 较可行，扫描件和重排版差异大。
- 实施难度：中到高。需要指纹版本、阈值、误判样本、回滚和算法迁移。
- 技术需求：指纹规范、结构摘要、置信度分级、阈值版本、人工确认和可解释的匹配依据。
- 兼容性：不上传全文时仍可实现，但指纹字段必须接受 D-17 的最小化与敏感性审查。
- 风险：误绑定会污染进度、笔记和引用；算法更新可能改变历史匹配结果。
- 验证：同名不同文档、删除封面、页码变化、不同 PDF 生成器、OCR 版本和大文件抽样碰撞测试。

### 4.4 方案 C 只允许用户显式绑定，不进行版本推断

规则：除完整内容哈希完全相同外，系统不推断版本关系。用户通过选择已有文档、导入身份清单或扫描配对码建立关联。

- 收益：系统行为最保守，几乎消除启发式误绑定。
- 可行性：高。
- 实施难度：低到中；技术简单，但交互设计和用户理解成本较高。
- 技术需求：显式绑定、撤销绑定、身份清单或配对载荷、重复绑定检测。
- 兼容性：与所有既有数据边界兼容。
- 风险：用户操作负担大，漏绑定率高；普通用户可能不理解身份与版本差异。
- 验证：跨端首次打开、版本升级、错误绑定撤销和无原文件设备恢复测试。

### 4.5 对比摘要

| 维度 | A 精确匹配加显式版本关联 | B 组合指纹 | C 完全显式绑定 |
|---|---|---|---|
| 误绑定风险 | 低 | 中 | 最低 |
| 漏绑定或操作负担 | 中 | 低到中 | 高 |
| 实验成本 | 低 | 高 | 中 |
| 对云端字段要求 | 低 | 中 | 低 |
| 与现有代码接近度 | 高 | 中 | 中 |

## 5 D-17 同步载荷与云端最小数据模型

### 5.1 所有方案共同禁止的数据

- 文档文件本体、完整解析结果和全文索引。
- 本地绝对路径、Android URI、Windows 用户目录和无必要的设备硬件标识。
- 未经本次授权的原文块、模型上下文或可批量还原全文的分段集合。
- 原文、令牌、密钥或完整笔记正文的日志副本。

### 5.2 最小对象候选

所有方案至少需要定义账号、设备会话、文档身份、文档版本、阅读进度、笔记、冲突副本、同步操作、同步游标和 tombstone。差异主要在笔记正文与摘录是否对服务端可见。

### 5.3 方案 A 服务端可读的最小结构化同步

规则：云端保存结构化进度、笔记正文和受长度限制的可选原文摘录；使用传输加密、服务端存储加密、访问控制和日志脱敏保护。

- 收益：实现和调试最直接；服务端可完成冲突副本、迁移、内容长度校验和数据导出。
- 可行性：高。
- 实施难度：中。
- 技术需求：字段字典、摘录长度限制、敏感级别、访问控制、存储加密、审计和数据导出/删除接口。
- 兼容性：符合 D-04，但必须证明摘录集合不会演变为云端全文索引。
- 风险：服务端数据泄漏影响更大；供应商或管理员理论上可读取笔记与摘录。
- 验证：载荷审计、越权测试、日志搜索、摘录累计量分析、备份恢复和删除核对。

### 5.4 方案 B 混合加密：元数据可读，笔记正文和摘录客户端加密

规则：文档身份、版本、revision、游标、操作类型和删除状态保持服务端可处理；笔记正文、冲突副本正文和原文摘录由客户端加密后上传。

- 收益：降低云端笔记和摘录泄漏风险，同时保留服务端同步排序、幂等和 tombstone 能力。
- 可行性：中到高。
- 实施难度：中到高。需要跨端密钥派生、设备新增、密钥轮换和恢复方案。
- 技术需求：账号级数据密钥、设备密钥封装、密文版本、认证加密、密钥恢复或恢复码、明文元数据清单。
- 兼容性：与 D-13 A 基本兼容；服务端不能理解正文，只能保存完整冲突密文副本。
- 风险：密钥丢失导致笔记不可恢复；元数据仍可能泄漏阅读行为；搜索和服务端迁移受限。
- 验证：双端解密、错误密钥、设备撤销、密钥轮换、密文篡改、恢复码和旧客户端兼容测试。

### 5.5 方案 C 全量端到端加密同步包

规则：除账号路由、设备会话、密文对象 ID、版本和最小传输控制字段外，进度、锚点、笔记、摘录和文档元数据均以不透明密文同步。

- 收益：云端可见数据最少，隐私边界最强。
- 可行性：中。
- 实施难度：高。
- 技术需求：完整密钥生命周期、客户端冲突合并、加密索引或完全本地检索、跨设备密钥交换和灾难恢复。
- 兼容性：服务端难以执行 D-13 的“最新有效进度”判断，可能需要把更多冲突逻辑下沉客户端。
- 风险：恢复和迁移复杂；实现错误可能同时造成数据泄漏和永久丢失。
- 验证：多设备加入、密钥丢失、恢复、撤销、乱序密文、客户端版本升级和服务端完全不可读证明。

### 5.6 对比摘要

| 维度 | A 服务端可读最小模型 | B 混合加密 | C 全量端到端加密 |
|---|---|---|---|
| 开发成本 | 低到中 | 中到高 | 高 |
| 云端隐私风险 | 中 | 低 | 最低 |
| 冲突与迁移能力 | 强 | 中 | 主要依赖客户端 |
| 密钥恢复风险 | 低 | 中到高 | 高 |
| 课程周期适配性 | 高 | 中 | 低到中 |

## 6 D-18 身份认证、设备会话和撤销模型

### 6.1 所有方案共同要求

- 使用随机生成的应用设备 ID，不使用 IMEI、硬盘序列号等硬件永久标识。
- 访问令牌短期有效，刷新令牌支持轮换和重放检测。
- 用户可以查看设备会话并撤销设备；撤销后旧令牌不能继续同步。
- Android 和 Windows 凭据存入平台安全存储，不写入普通配置文件或日志。
- 退出账号、撤销设备与删除本地数据是不同动作，必须明确提示。

### 6.2 方案 A 自建个人账号和令牌服务

规则：项目自行管理用户名或邮箱、密码哈希、登录、访问令牌、刷新令牌、设备会话和恢复流程。

- 收益：控制力强，演示链路完整，不依赖外部身份供应商。
- 可行性：中到高。
- 实施难度：中到高；密码安全和恢复流程容易被低估。
- 技术需求：强密码哈希、登录限速、令牌签发与轮换、设备表、邮件或恢复码、审计和密钥轮换。
- 兼容性：与 D-11 B 的身份同步服务边界直接兼容。
- 风险：自建认证出现安全缺陷；邮件恢复和滥用防护增加运维范围。
- 验证：撞库限速、令牌重放、刷新令牌轮换、设备撤销、密码修改后会话失效和时钟偏差测试。

### 6.3 方案 B 外部 OIDC 身份提供方，项目管理设备会话

规则：登录和账号恢复交给标准 OIDC 提供方；项目服务验证身份令牌，并独立维护应用设备会话、同步授权和撤销状态。

- 收益：减少密码存储和恢复风险；采用标准协议。
- 可行性：中，依赖账号、网络、回调和提供方配置。
- 实施难度：中。
- 技术需求：OIDC 授权码加 PKCE、回调处理、令牌验证、提供方主体映射、设备会话和断网恢复。
- 兼容性：不改变 D-09 的单用户工作区；外部身份不等于团队成员体系。
- 风险：外部服务不可用、账号政策变化、课堂网络受限和身份主体迁移。
- 验证：首次登录、令牌过期、提供方断网、主体变更、撤销设备和账号删除测试。

### 6.4 方案 C 受限注册或预置演示账号

规则：一期只允许邀请码、预置账号或少量受控注册；仍使用正式设备会话和令牌，但不建设开放注册和复杂账号恢复。

- 收益：范围最小，适合课程演示和有限用户验证。
- 可行性：高。
- 实施难度：低到中。
- 技术需求：账号预置或邀请码、令牌、设备会话、密码重置管理流程和明确的非生产限制。
- 兼容性：满足个人账号与同步，但弱化真实产品的自助注册和恢复能力。
- 风险：若文档未标明限制，容易被误解为生产级认证；人工账号管理不可扩展。
- 验证：多设备登录、设备撤销、账号禁用、凭据泄漏处理和演示环境重建。

### 6.5 对比摘要

| 维度 | A 自建账号 | B 外部 OIDC | C 受限注册/预置账号 |
|---|---|---|---|
| 外部依赖 | 低 | 高 | 低到中 |
| 安全实现责任 | 高 | 中 | 中 |
| 账号恢复完整性 | 可完整但成本高 | 由提供方承担 | 有限 |
| 演示稳定性 | 中到高 | 受网络影响 | 高 |
| 产品扩展性 | 高 | 高 | 低 |

## 7 D-19 删除、撤权、tombstone 和保留期

### 7.1 必须先分开的动作

| 动作 | 立即效果 | 是否一定删除云端数据 |
|---|---|---|
| 撤销本地文件授权 | 立即停止读取、检索和模型外发，清理本地派生数据 | 否，进度和笔记需由用户另行决定 |
| 从本地工作区移除文档 | 清理本地解析、索引和缓存 | 否，可保留云端笔记和进度以供重新授权恢复 |
| 删除笔记或同步记录 | 产生 tombstone，阻止离线设备复活 | 是，经过保留期后硬删除 |
| 退出账号 | 令牌失效或从当前设备移除会话 | 不自动等同于账号删除 |
| 撤销设备 | 服务端拒绝该设备令牌和后续上传 | 不保证远程擦除设备已有本地文件 |
| 删除账号 | 阻断登录，启动个人云端数据清理 | 是，但备份和审计例外需说明 |

### 7.2 方案 A 固定短期 tombstone 加异步硬删除

规则：删除立即对业务不可见并拒绝旧版本写入；tombstone 保留固定候选周期，期满后异步硬删除。候选周期必须经长期离线测试后确定，不能直接写成正式 SLA。

- 收益：规则简单，存储可控，易于解释。
- 可行性：高。
- 实施难度：中。
- 技术需求：删除 revision、删除时间、清理任务、保留期配置、拒绝旧 `baseRevision` 和清理审计。
- 兼容性：与 D-13 A 高度兼容。
- 风险：离线时间超过保留期的旧设备可能重新上传；固定周期可能过短或过长。
- 验证：超过候选周期的离线设备、删除与编辑竞争、备份恢复、清理任务失败和重复删除测试。

### 7.3 方案 B 用户可恢复窗口加 tombstone

规则：删除进入用户可见回收期；回收期内允许恢复，仍保留 tombstone 或删除状态。回收期结束后进入不可恢复清理。

- 收益：降低误删损失，用户体验更友好。
- 可行性：高。
- 实施难度：中到高；恢复与并发编辑语义更复杂。
- 技术需求：回收状态、恢复 revision、恢复权限、跨端回收列表、清理任务和恢复冲突规则。
- 兼容性：与 D-13 A 兼容，但必须决定恢复是否覆盖删除后的新建同名对象。
- 风险：用户误以为删除已立即清除；隐私删除诉求与可恢复期冲突。
- 验证：删除后跨端恢复、恢复与重建竞争、回收期到期和立即永久删除入口测试。

### 7.4 方案 C 设备确认水位加 tombstone 压缩

规则：服务端记录每个活跃设备确认的变更水位；只有所有未撤销设备越过删除序号，或达到最大安全期限后，才压缩 tombstone。长期离线设备需重新全量同步或更新账号数据世代。

- 收益：对长期离线和删除复活的控制最强，能安全压缩历史记录。
- 可行性：中。
- 实施难度：高。
- 技术需求：设备确认水位、活跃设备集合、账号世代或同步 epoch、游标失效、全量重建和强制重新认证。
- 兼容性：与 D-18、D-21 紧密耦合；不能独立实现。
- 风险：状态机和运维复杂；失联设备会阻塞清理，撤销设备处理错误会造成数据丢失。
- 验证：多设备不同水位、设备撤销、游标过期、账号世代切换和 tombstone 压缩属性测试。

### 7.5 对比摘要

| 维度 | A 固定保留期 | B 可恢复窗口 | C 设备水位压缩 |
|---|---|---|---|
| 实现复杂度 | 中 | 中到高 | 高 |
| 误删恢复 | 无或仅后台 | 强 | 可另行增加 |
| 长期离线防护 | 中 | 中 | 强 |
| 隐私删除解释 | 清晰 | 需解释恢复期 | 需解释设备水位 |
| 与 D-21 耦合 | 中 | 中 | 高 |

## 8 D-20 本地数据存储与加密边界

### 8.1 建议独立管理的数据类别

| 数据类别 | 生命周期和敏感性 |
|---|---|
| 原文件授权和定位信息 | 平台专属；撤权后立即失效；路径或 URI 不进云 |
| 文档元数据和阅读进度 | 小型结构化数据；需要迁移、备份策略和账号隔离 |
| 笔记与摘录 | 敏感数据；需要加密、删除和同步队列保护 |
| 解析结果和全文索引 | 可能还原原文；仅本地；随文件撤权或文档移除清理 |
| 缩略图、缓存和临时文件 | 可再生成；应设置容量和清理策略 |
| 令牌和数据密钥 | 高敏感；只能进入平台安全存储 |
| 导出临时文件 | 用户指定前保持最短生命周期，失败后可清理 |

### 8.2 方案 A 分层存储，主要依赖操作系统数据保护

规则：结构化元数据和笔记进入本地数据库；全文索引和大缓存独立存储；凭据进入平台安全存储；普通业务数据主要依赖 Android 应用沙箱、Windows 用户权限和磁盘保护。

- 收益：实现简单，搜索和迁移成本低。
- 可行性：高。
- 实施难度：中。
- 技术需求：数据目录清单、平台权限、凭据安全存储、数据库迁移、缓存清理和备份排除。
- 兼容性：与分端平台适配和共享数据契约兼容。
- 风险：设备已解锁、备份复制或本地管理员场景下，笔记和索引可能明文可读。
- 验证：应用沙箱检查、Windows 文件权限、系统备份、卸载残留、数据库复制和崩溃恢复测试。

### 8.3 方案 B 分层存储加选择性应用层加密

规则：维持数据库、索引和缓存分层；笔记正文、摘录、同步队列载荷和关键身份字段使用应用数据密钥加密；令牌和密钥由平台安全存储保护。全文索引是否加密单独依据性能实验决定。

- 收益：在可维护性和敏感数据保护之间平衡；不会强迫所有搜索索引承担加密开销。
- 可行性：中到高。
- 实施难度：中到高。
- 技术需求：字段或记录级认证加密、密钥版本、轮换、数据库迁移、Android Keystore、Windows 凭据保护和故障恢复。
- 兼容性：与 D-17 A 或 B 都可组合；共享核心只定义加密端口，不持有平台密钥实现。
- 风险：遗漏字段形成明文旁路；查询、排序和迁移受限；密钥失效导致局部数据不可读。
- 验证：文件和数据库取证检查、密钥轮换、旧版本迁移、密文篡改、设备锁屏和恢复测试。

### 8.4 方案 C 整个本地工作区加密

规则：数据库、索引、缓存和派生数据统一放入加密数据库或加密容器；只有应用运行并获得平台密钥后解锁。

- 收益：静态数据保护边界最清晰，减少明文字段遗漏。
- 可行性：中。
- 实施难度：高，尤其是全文索引、随机访问、大文件缓存和崩溃恢复。
- 技术需求：加密数据库或容器、密钥恢复、锁定状态、索引性能验证、原子写入和损坏修复。
- 兼容性：可能增加 Android 和 Windows 平台差异；共享核心不能假设相同加密库。
- 风险：性能下降、容器损坏影响范围大、密钥丢失造成整个工作区不可恢复。
- 验证：大索引查询、异常终止、密钥轮换、容器损坏、空间回收和最低配置设备性能测试。

### 8.5 对比摘要

| 维度 | A 操作系统保护为主 | B 选择性应用加密 | C 全工作区加密 |
|---|---|---|---|
| 实施成本 | 低到中 | 中到高 | 高 |
| 明文旁路风险 | 中 | 低到中 | 低 |
| 搜索性能影响 | 低 | 低到中 | 中到高 |
| 密钥丢失影响 | 主要是凭据 | 部分敏感数据 | 整个工作区 |
| 双端验证成本 | 中 | 中到高 | 高 |

## 9 D-21 同步协议与客户端状态机

### 9.1 协议共同要求

- 上传操作使用客户端生成的 `operationId` 保证幂等。
- 每个可同步对象携带 `itemId`、`baseRevision`、文档身份和版本信息。
- 服务端分配可信 revision 或变更序号，不依赖客户端墙钟决定冲突。
- 拉取使用有界批次；部分成功必须逐项返回，不能把整个批次状态含糊化。
- 瞬时失败使用退避和抖动；权限、版本或协议错误进入终态或待人工处理。
- 游标失效时进入明确的重新基线流程，不得静默清空本地队列。
- 协议版本必须有兼容窗口和最低支持版本。

### 9.2 方案 A 操作上传加游标变更流

规则：客户端持久化离线操作日志，分批上传；服务端按账号生成单调变更序号；客户端用游标增量拉取变更并应用。推送通知只作为触发，不携带业务真相。

- 收益：适合离线优先、批次同步和 D-13 A；现有实验与该方向接近。
- 可行性：高。
- 实施难度：中到高；真实服务端需要事务和游标一致性。
- 技术需求：操作表、幂等表、变更流、游标、批次限制、逐项结果、重试策略和全量重建接口。
- 兼容性：与 D-11 B 的身份同步服务和 KMP 共享状态机候选兼容。
- 风险：上传成功但响应丢失、游标推进与本地应用不原子、变更流无限增长。
- 验证：响应丢失重放、重复上传、乱序变更、批次部分失败、游标过期、进程终止和协议升级测试。

### 9.3 方案 B 资源版本条件更新加周期拉取

规则：笔记、进度和删除分别使用资源接口；客户端通过 `If-Match`、revision 或 ETag 条件更新，按更新时间或版本分页拉取。

- 收益：接口直观，服务端实现和调试较简单。
- 可行性：高。
- 实施难度：中。
- 技术需求：资源版本、条件请求、分页、删除标记、幂等键和客户端轮询调度。
- 兼容性：可实现 D-13 A，但多个资源类型的统一游标和跨对象顺序较弱。
- 风险：更新时间分页可能漏数据；批量离线操作请求数多；全局删除传播和游标恢复不够自然。
- 验证：同时间戳分页、条件失败、重复请求、多资源乱序、断点恢复和大量离线操作测试。

### 9.4 方案 C 追加事件日志复制

规则：所有变更作为不可变事件追加，客户端和服务端通过日志位置复制并重建对象状态；快照用于压缩历史。

- 收益：审计、重放和冲突分析能力强，天然保留操作历史。
- 可行性：中。
- 实施难度：高。
- 技术需求：事件模式版本、聚合重建、快照、压缩、事件幂等、隐私删除和投影一致性。
- 兼容性：与 D-11 B 可兼容，但对一期个人同步可能过度复杂；删除和隐私硬删除更难解释。
- 风险：事件历史包含敏感数据；模式演进和快照错误可能破坏重放。
- 验证：全量重放、跨版本事件、快照恢复、删除净化、重复事件和投影故障测试。

### 9.5 客户端状态候选

无论采用哪种协议，客户端至少应区分：

`Synced`、`DirtyQueued`、`Uploading`、`RetryableError`、`Rejected`、`Conflict`、`DeletedPending`、`RebaseRequired`。

UI 不需要展示全部内部状态，但必须能解释“等待同步、冲突、需要重新登录、文件版本不匹配和删除处理中”。

### 9.6 对比摘要

| 维度 | A 操作加游标 | B 资源条件更新 | C 事件日志复制 |
|---|---|---|---|
| 离线批次能力 | 强 | 中 | 强 |
| 实现复杂度 | 中到高 | 中 | 高 |
| 审计和重放 | 中 | 低到中 | 强 |
| 删除与隐私处理 | 中 | 直观 | 较复杂 |
| 与现有实验接近度 | 高 | 中 | 低 |

## 10 跨决策兼容性

### 10.1 组合约束

1. D-16 B 的结构指纹会增加 D-17 的云端字段和隐私审查范围。
2. D-17 C 会使服务端无法直接判断进度有效性，D-13 A 的部分规则需转到客户端。
3. D-18 的设备撤销必须参与 D-19 C 的活跃设备水位计算。
4. D-19 C 依赖 D-21 A 或 C 提供稳定的全局序号和设备确认水位。
5. D-20 A 与 D-17 B/C 组合时，云端密文更安全，但本地解密后的数据库仍可能明文保存。
6. D-21 B 可以降低服务端实现成本，但需要特别证明不会因分页和时间排序漏掉删除。

### 10.2 代表性组合，不构成推荐

| 组合 | 特征 | 主要代价 |
|---|---|---|
| 组合 P：D-16 A、D-17 A、D-18 C、D-19 A、D-20 A、D-21 B | 最小课程实现，外部依赖少 | 隐私保护和长期离线防护较弱，产品化迁移工作多 |
| 组合 Q：D-16 A、D-17 B、D-18 A或B、D-19 A、D-20 B、D-21 A | 在工程成本、隐私和离线同步之间平衡 | 需要密钥、真实认证和游标服务端验证 |
| 组合 R：D-16 B、D-17 C、D-18 B、D-19 C、D-20 C、D-21 C | 隐私、版本推断和历史能力最强 | 实现、验证和恢复复杂度最高，明显挤压课程周期 |

## 11 最小验证清单

本批选择后，验证计划至少应覆盖：

| 验证项 | 覆盖决策 | 通过证据 |
|---|---|---|
| 相同文件、改名、轻微编辑、重导出和同名不同文件匹配 | D-16 | 匹配矩阵、误绑定和漏绑定结果 |
| 同步载荷字段与累计摘录审计 | D-17 | 字段字典、样本载荷、敏感分级和日志检查 |
| 登录、令牌轮换、设备撤销和离线重连 | D-18 | 自动化接口测试和双端操作记录 |
| 删除与编辑竞争、长期离线和备份恢复 | D-19 | tombstone 状态、清理记录和复活防护结果 |
| 数据目录、加密、迁移、卸载残留和密钥失效 | D-20 | 文件系统检查、迁移测试和恢复结果 |
| 重复、乱序、响应丢失、部分失败和游标失效 | D-21 | 协议测试向量和双端状态机结果 |

现有 Android 最小工程只能覆盖其中一部分，不得用单端模拟结果替代真实服务端和 Windows 端验证。

## 12 集中选择格式

请由当前对话人一次性选择：

`D-16 ?；D-17 ?；D-18 ?；D-19 ?；D-20 ?；D-21 ?`

可以使用 A、B、C，也可以指定组合或附加约束。例如：`D-17 B，但一期不提供云端笔记搜索`。收到选择后，应创建新的集中决策清单版本、Proposed ADR 和架构视图增量，并同步更新需求映射、架构驱动因素和质量属性场景。
