## 3 D-22至D-35选择摘要

| 决策 | 选择 | 结果 |
|---|---|---|
| D-22 | A | Android和Windows使用各自成熟文档组件，通过统一页面、坐标、能力、解析版本和降级合同对齐 |
| D-23 | B | 客户端本地全文/BM25与固定中文嵌入模型形成混合检索，不上传全文或向量索引 |
| D-24 | A | 权限过滤、检索、重排和证据裁剪在客户端完成，服务端只验证证据包并调用模型 |
| D-25 | A | 结构锚点与字符锚点并存并绑定DocumentVersion；跨版本默认stale，不自动迁移 |
| D-26 | A | 客户端持久任务队列；服务端PostgreSQL任务表；事件限于状态通知与审计 |
| D-27 | A | REST/JSON主协议，AI使用SSE并提供轮询回退 |
| D-28 | A | KMP共享领域、同步、合同和测试；UI与平台能力分端实现 |
| D-29 | A | OpenAI官方Responses API，固定gpt-5.4-mini-2026-03-17候选快照 |
| D-30 | A | PostgreSQL承担同步事务、幂等、账号变更流和数据库任务表；一期不强制消息代理或通用缓存 |
| D-31 | A | TLS、基础设施静态加密、KMS/Secret Manager、平台安全凭据、最小权限和日志脱敏 |
| D-32 | A | 最小结构化日志、指标和有限追踪；使用脱敏关联ID；诊断包由用户主动导出 |
| D-33 | B | 文本型PDF、复杂版式和扫描PDF分别设定预算和降级路径，数值待实验 |
| D-34 | A | 风险驱动双端最小正式测试矩阵 |
| D-35 | A | 三个逻辑责任单元可同机部署，PostgreSQL加数据库任务表；满足收口门槛后才最终冻结 |

## 4 决策依赖与关闭顺序

1. 先完成D-22、D-23、D-25的双端文档、检索和引用金标。
2. 完成D-24、D-27、D-29的证据外发、SSE和正式模型API验证。
3. 完成D-26、D-30的客户端任务恢复和PostgreSQL事务/任务表故障实验。
4. 完成D-28的KMP双端构建、打包、桥接量和测试复用门槛。
5. 完成D-31、D-32的威胁建模、密钥轮换、日志扫描和故障诊断。
6. 依据上述结果关闭D-33正式阈值。
7. 依据决策—测试双向追踪评审D-34。
8. 只有前述关键项关闭或登记正式风险接受后，才评审D-35和各ADR是否转Accepted。
