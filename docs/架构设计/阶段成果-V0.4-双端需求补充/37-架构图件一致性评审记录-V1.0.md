## 1 评审目的和范围

本记录用于审核系统上下文、逻辑分层、组件、运行单元、部署、数据流、时序、状态、信任边界与故障降级图是否与正式决策、ADR、数据边界和验证状态一致。角色 A 只提出一致性问题和验收意见，不替代角色 D 改变架构含义。

## 3 历史图件冲突记录

历史图件包含团队工作区、公开/好友分享、Flutter、macOS/iOS 或其他当前基线外内容，与一期“个人用户、Android 12+、Windows 11、本地优先、主动导出”的正式边界冲突。若复用其布局或视觉元素，必须重新绘制责任与数据流，并明确删除以下内容：

1. 团队空间、组织角色、协同编辑和公开链接。
2. Web、macOS、iOS 或 Flutter 作为正式客户端技术栈。
3. 云端文档本体、全文索引、向量库或服务端主动抓取本地文件。
4. 每项业务能力一个微服务和默认消息中间件。
5. 独立管理员产品；一期只能表达受限运维、审计和任务观察能力。
6. 未经用户同意直接向模型发送正文或整份文档。

历史图件不得仅通过改标题变成当前图件，必须按本记录逐项复核。

## 6 跨文档一致性检查

| 检查项 | 正式口径 | 图件验收方法 |
|---|---|---|
| 决策状态 | D-11 至 D-35 已选择，ADR Proposed | 图例必须区分 Selected/Proposed/Validated/Final |
| 服务数量 | 三个逻辑责任单元，可同机 | 不以方框数量暗示必须独立部署 |
| 数据位置 | 文档/索引仅客户端，服务端最小结构化数据 | 检查每条数据箭头的源、目的和留存 |
| KMP | 共享领域、同步、合同和测试 | shared 方框不得包含 UI/文件/数据库/后台任务 |
| 文档引擎 | 分端成熟组件 + 统一合同 | Android/Windows 组件分别画，合同位于边界 |
| RAG | 客户端检索/裁剪，网关校验/调用 | 不允许模型或服务端直接访问本地文档 |
| 同步 | operation/revision/cursor/tombstone | 时序需包含幂等、REBASE 和重复请求 |
| 任务 | 平台持久任务 + PostgreSQL 任务表 | 不默认加入消息代理 |
| 部署 | 云中立 + 华为云能力映射 | 两张图语义一致，产品映射不改变合同 |
| SLA | 候选测量点，不是正式阈值 | 图上不得写成正式 10/30/60 秒承诺 |

## 8 图件提交格式要求

1. 每张图应包含编号、标题、版本、状态、输入决策和更新时间。
2. 图例区分业务能力、逻辑模块、代码组件、进程、部署节点、数据存储和外部系统。
3. 数据箭头标注协议、数据类别、授权条件和是否持久化。
4. Proposed 元素使用统一样式；未经验证不得标记 Accepted/Final。
5. 源文件与导出图同时保留，避免只提交不可编辑图片。
6. 图件名称和引用应与 33/36/38 的索引一致。

## 9 初始评审结论

当前只能确认 24 V1.3 的文字视图与 35/36 的组合架构口径一致，无法对角色 D 的正式图件作通过结论。历史图件存在显著范围冲突，应维持“历史参考”状态。角色 D 提交当前图件后，角色 A 应按 ARCH、FLOW 和问题清单逐图复核，并把结果分为通过、条件通过、必须修复、等待实验或需要重新打开决策。
