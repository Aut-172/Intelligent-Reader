## ADR-011 少量粗粒度服务

- 状态：Proposed
- 对应决策：D-11 B
- 上下文：本地优先客户端仍需要账号同步、在线 AI 和异步任务。细粒度微服务会超出课程周期，但单一部署单元会把 AI 故障、同步和任务资源竞争混在一起。
- 决策：采用身份与同步、AI/RAG、任务与审计等少量粗粒度责任单元。独立工作进程可以是部署单元，不要求每个模块成为独立网络服务。
- 正向后果：故障和资源边界更清晰；AI 故障不阻断同步；任务并发可独立控制。
- 负向后果：需要跨服务契约、关联 ID、幂等和补偿；存在分布式单体风险。
- 约束：不得共享隐式数据库事务；服务数据所有权由 D-17/D-21/D-30 关闭。
- 验证：故障隔离、重复请求、跨服务部分失败、干净环境部署。
- 重新打开：服务数量造成无法维护的部署成本，或数据边界无法成立。

## ADR-012 KMP 单路线验证

- 状态：Proposed
- 对应决策：D-12 A
- 上下文：Windows 已有 KMP/Compose Desktop 证据，Android 已有纯 Kotlin/JVM 最小工程，但尚无真实 KMP 双端同核证据。
- 决策：下一轮只补齐 KMP Android 与 Windows 双端共享核心、相同测试向量和构建门禁，不启动 Rust 或 Qt 新实验。
- 正向后果：以最低新增成本关闭最关键的 Android 和共享核心缺口。
- 负向后果：缺少同时期 Rust/Qt 横向实证，可能形成路径依赖。
- 约束：不能把当前 `kotlin.jvm` shared 模块称为 KMP；D-28 才选择最终技术栈。
- 验证：双端同 source set、序列化一致性、Android 12、release-like 制品、构建与桥接成本。
- 重新打开：KMP 门禁失败，或出现 Rust/Qt 能回答的明确阻塞。

## ADR-013 保守同步冲突策略

- 状态：Proposed
- 对应决策：D-13 A
- 上下文：双端可能离线修改笔记和进度。关键笔记不应因简单覆盖静默丢失，删除也不能被旧设备复活。
- 决策：笔记保留冲突副本；进度使用服务端可信顺序选择最新有效记录；删除产生版本化 tombstone。
- 正向后果：规则可解释、可测试，适合个人用户低并发。
- 负向后果：需要冲突 UI、额外存储和 tombstone 生命周期管理。
- 约束：不同 DocumentVersion 的记录不能直接比较或合并；保留期和清理由 D-19/D-21 决定。
- 验证：并发编辑、删除竞争、重复与乱序、设备撤销、长期离线。
- 重新打开：冲突频率或人工处理成本显著超过假设，或引入多人实时协作。

## ADR-014 云中立部署加华为云映射

- 状态：Proposed
- 对应决策：D-14 A
- 上下文：课程需要可实施的部署说明，但不应让业务设计依赖特定云 SDK 或账号配额。
- 决策：使用容器/标准运行包、关系数据库、可选任务队列、密钥和可观测能力描述正式部署基线，并提供华为云候选产品类别映射。
- 正向后果：保持可移植性，同时满足具体云部署说明。
- 负向后果：需要额外维护通用基线和云产品映射；抽象设计可能缺少真实部署证据。
- 约束：云端不得保存文档本体、全文索引或默认可还原全文的数据。
- 验证：空白环境部署、迁移、重启、备份恢复和华为云能力映射核对。
- 重新打开：验收要求强制指定云产品，或云中立基线无法支持必要能力。

## ADR-015 单一外部模型供应方适配

- 状态：Proposed
- 对应决策：D-15 A
- 上下文：一期需要控制接入、合规、测试和费用范围，同时保留未来替换能力。
- 决策：只接入一个外部模型供应方，通过内部适配器隔离 SDK、请求、流式、取消、限流和错误。具体供应方和模型由 D-29 决定。
- 正向后果：验证范围和运营复杂度最低；业务层可以保持稳定契约。
- 负向后果：供应方故障会使在线生成整体不可用；适配器可能泄漏供应方特性。
- 约束：逐文件同意、最少证据外发、无原文日志；不得自动切换到未获同意的第二供应方。
- 验证：超时、限流、取消、断流、替换桩、数据流和日志审计。
- 重新打开：稳定性、政策、费用或质量无法满足一期，或项目明确批准备用/自托管端点。
